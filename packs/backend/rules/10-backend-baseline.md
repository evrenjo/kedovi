## 백엔드 기본 원칙

백엔드 코드를 고치기 전에 이 목록을 훑는다. 스택 팩 룰은 이 위에 그 기술의 구체 규칙만 더한다.

- **기존 관례가 먼저** — 응답·오류 형식, 예외 계층, 메시지, 계층 구조, 로그 형식은 **이미 있는 코드에서 찾아 따른다.** 새 봉투·오류 코드 체계를 혼자 들이지 않는다. 관례가 없을 때만 안을 내고 사람에게 묻는다. 만들기 전에 같은 일을 하는 코드가 있는지 찾고, 생성된 코드는 손대지 않고 원본에서 다시 만든다.
- **인가는 매 요청, 객체 단위로** — 로그인 여부만 보지 않는다. 요청한 ID 의 행이 이 사용자 것인지 서버에서 확인한다. 기본은 거부, 판정은 공용 헬퍼로.
- **입력은 경계에서 검증** — 허용 목록·길이·범위를 저장 컬럼과 맞추고 필드 단위 오류로. 요청을 저장 모델에 통째로 바인딩하지 않고, 저장 모델을 그대로 응답하지 않는다.
- **쿼리는 파라미터 바인딩만** — 문자열에 입력값을 잇지 않는다. 바인딩 안 되는 자리(정렬 컬럼 등)는 허용 목록.
- **시크릿은 코드·로그·오류 응답에 두지 않는다** — 설정·비밀은 코드 밖(환경·비밀 저장소, 프로젝트 방식)에서 읽는다. 비밀번호·토큰·개인정보는 로그 금지, 실제 고객 데이터를 테스트 픽스처·커밋에 넣지 않는다.
- **오류를 삼키지 않는다** — 4xx(업무 거부)와 5xx(예상 못 한 오류)를 구분, 변환은 전역 처리기 한 곳. 응답에 스택트레이스·내부 경로·원문 예외를 싣지 않고, 사용자 문구는 프로젝트 메시지 체계로(치환 인자).
- **트랜잭션은 서비스 단위** — 오류를 돌려주며 앞서 바꾼 데이터가 커밋되면 결함이다. 트랜잭션 안에서 외부 호출을 기다리지 않는다.
- **외부 호출엔 타임아웃** — 재시도는 멱등 작업만, 지수 백오프+지터·상한. 재시도될 수 있는 쓰기는 멱등하게.
- **자원엔 상한이 있다** — 페이지 크기·본문·업로드 최댓값, 비싼 작업엔 호출 한도. 상태 변경을 GET 으로 만들지 않는다.
- **API 는 깨지 않고 더한다** — 필드·의미·상태 코드를 바꾸거나 지우는 것은 사람 승인 뒤 버전·폐기 공지로.
- **바꾼 동작엔 테스트** — 버그 수정은 실패하는 재현 테스트부터. 실행 허용 여부는 project 팩 규칙.

세부는 작업 전에 「백엔드 …」 on-demand 룰(계층·API·데이터·로깅·보안·외부 호출·테스트·쓰기 보고서)을 읽는다. 근거 출처는 `packs/backend/docs/SOURCES.md`.
