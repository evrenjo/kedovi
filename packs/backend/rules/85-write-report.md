## 쓰기 보고서: 저장 로직 변경

쓰기 보고서 = 시험이 DB 에 무엇을 어떻게 썼는지 테이블 · 행으로 남긴 것(형식 정본 `packs/core/assets/write-report/FORMAT.md`, 사람용 설명 킷 문서 「쓰기 보고서」).

- **쓰기 보고서를 아직 안 붙인 repo** (설정 파일 `write-report.properties` · `write-report.json` 이 없음): 저장 로직을 바꾸는 작업이면 `kedovi writes add <스택>`(jooq · jdbc · sqlalchemy · node-pg)을 사용자에게 권하고, 붙이기로 하면 `--dry-run` 으로 넣을 파일을 먼저 보인다. 붙이지 않기로 하면 아래 표를 손으로 만든다.
- **바꾼 저장 경로의 시험을 돌려 보고서를 새로 만든다.** 기능 ID(수용 기준 ID)를 시험 이름 · 태그 · `@spec` 에 붙여 보고서가 기능별로 묶이게 한다.
- **기대값(승인본)은 사용자 확인 뒤에만 갱신한다.** 승인본과 다르면 시험이 실패하고 받은 값이 `received/` 에 남는다. 차이(테이블 · 컬럼 · 전 → 후)를 보이고, 의도한 변경이라고 사용자가 확인하면 그때 승인 모드(`writeReport.approve=true` · `WRITE_REPORT_APPROVE=1`)로 갱신한다. 시험을 통과시키려고 에이전트가 혼자 승인본을 바꾸지 않는다.
- 승인본은 핵심 테이블만 고정한다 (그 시험이 지키려는 테이블. 전부 고정하면 상관없는 변경에도 깨진다).
- **완료 보고에 그 테이블을 붙인다**: 보고서 화면 경로(`kedovi writes open`) 또는 표 `| 테이블 | 컬럼 | 전 | 후 |` (값은 정규화 · 마스킹된 보고서 값 그대로). 승인본을 갱신했으면 무엇을 갱신했는지 한 줄.
- 기획 repo 기능 문서에 「저장」 표가 있으면 `kedovi writes check` 로 대조하고, 표에 없는 쓰기 · 타입 범위 위험(✖)을 보고에 옮긴다. 표와 코드 중 무엇이 맞는지는 문서 규칙(기획 문서 쓰기)의 판정 순서를 따른다.
