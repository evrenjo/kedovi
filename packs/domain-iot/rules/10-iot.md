## IoT: 명세 단위 · 검증 단계 · 사람 관문

### 명세 단위

- 기능 문서 = 요구사항 단위. 요구마다 인터페이스 계약(`IF-번호`: MQTT 주제 · 메시지) · 대상 보드 판(`HW-번호`) · 위협(`HAZ-번호`)을 잇는다 (`docs-site/기능/_template.md`).
- **인터페이스 계약이 먼저다.** 주제 · 메시지 형식은 코드 repo 의 AsyncAPI 파일(`asyncapi.json` 이나 `.yaml`)이 정본이다. 문서 사이트가 JSON 을 채널 표로 보여 준다. 계약을 바꾸면 상대 장치 · 서비스 쪽 영향을 함께 찾는다.
- V 모델 추적: 요구마다 어느 시험 단계에서 확인하는지 검증 표에 적는다.

### 코딩 규칙 · 예산

- 프로젝트가 정한 규칙 집합(MISRA C · CERT C 등) · 정적 분석 도구 · 금지 API 목록을 먼저 찾아 따른다. 정한 것이 없으면 정하자고 제안한다. 예외는 결정 문서로 남긴다.
- MCU · RTOS · SDK 판과 메모리 · 전력 예산은 펌웨어 문서가 정본이다.
- OTA 는 실패해도 장치가 살아야 한다: 서명 확인 · 되돌림 · 단계 배포를 지킨다. 비밀 키 · 장치 인증서를 코드 · 로그에 남기지 않는다.

### 검증 단계 (AI 구현 뒤)

| 단계 | 하는 일 | 남기는 곳 |
|---|---|---|
| 정적 분석 | 규칙 검사 | 기능 문서 검증 표 (단계 · 결과 · 어디서) |
| 단위 | 호스트에서 단위 시험 | 같은 표 |
| 에뮬레이터 | QEMU · Renode · Wokwi 에서 펌웨어 실행 | 같은 표 |
| HIL 농장 | CI 가 실제 보드에 굽고 시리얼 로그로 확인 | 같은 표 (보드 판 `HW-번호` · CI 작업) |
| 현장 원격 측정 | 현장 장치 지표 (끊김 · 배터리 · 메시지 유실) | 현장 시험 문서 |

- **컴파일 통과만으로 완료가 아니다.** 돌리지 못한 단계는 「아직」 으로 두고 기능을 완료로 넘기지 않는다.

### 사람 관문: 멈추고 묻는다

아래는 에이전트가 하지 않는다. 할 일 · 명령 · 근거를 보여 주고 사람 확인을 요청한 뒤 기다린다.

- 하드웨어 기동 · 실제 장치에 굽기 · 현장 장치에 OTA 배포
- 보안 판정 (EN 303 645 · IEC 62443 등 해당 기준), 장치 키 · 인증서 발급
- EU 사이버 복원력법 대상 여부 · SBOM 공개
- 안전 (IEC 61508 · ISO 26262, 해당할 때) 판정

### 에이전트 도구 (있으면 쓴다)

- 이 세션에 장치 MCP(ESP-IDF MCP · Wokwi MCP 등)나 Renode 가 있으면 빌드 · 에뮬레이터 실행 · 로그 읽기에 쓴다. 없으면 SDK 명령줄로 하고, 그것도 안 되면 사람이 돌릴 명령을 알려 준다.
- 굽기 · OTA 도구가 있어도 위 사람 관문은 그대로 지킨다.
