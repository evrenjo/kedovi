## 게임: 명세 단위 · 검증 단계 · 사람 관문

### 명세 단위

- 기능 문서 하나 = 메카닉 · 시스템 하나. 규칙 · 상태 · 입력 · 조정값을 표로 쓴다 (`docs-site/기능/_template.md`).
- **조정값은 코드에 박지 않는다.** 정본은 밸런스 표(`docs-site/설계/밸런스/`, ID `BAL-번호`, 수치는 CSV · JSON)다. 코드는 그 데이터를 읽는다.
- 엔진 판 · 플랫폼별 성능 예산(프레임 · 메모리)은 개발 표준 문서에 적고, 바꾸는 코드는 그 예산 안에 둔다.
- 세이브 · 네트워크 메시지 형식은 인터페이스 명세로 남긴다 (실시간 메시지는 AsyncAPI 파일을 코드 repo 에 두면 문서 사이트가 채널 표로 보여 준다).

### 검증 단계 (AI 구현 뒤)

| 단계 | 하는 일 | 남기는 곳 |
|---|---|---|
| 에디터 자동 시험 | 엔진 자동 시험을 헤드리스로 돌린다 | 기능 문서 검증 표 (단계 · 결과 · 어디서) |
| 봇 시뮬레이션 | 여러 판을 돌려 지표(승률 · 재화 · 판 시간)를 바꾸기 전과 비교 | 같은 표 + 밸런스 표의 바꾼 이유 |
| 사람 플레이테스트 | 사람이 한다. 에이전트는 빌드 · 확인할 것 목록만 준비 | 플레이테스트 문서 |

- **빌드 · 컴파일 통과만으로 완료가 아니다.** 돌리지 못한 단계는 결과를 「아직」 으로 두고 기능을 완료로 넘기지 않는다.
- 어디서 칸에는 엔진 판 · 맵 · 판 수처럼 다시 돌릴 수 있는 정보를 적는다.

### 사람 관문: 멈추고 묻는다

아래는 에이전트가 정하지 않는다. 결과물과 근거(스크린샷 · 시뮬레이션 지표)를 보여 주고 사람 확인을 요청한 뒤 기다린다.

- 아트 확정: AI 가 만든 이미지 · 모델 · 소리는 임시 에셋으로 표시하고 에셋 목록의 상태를 「임시」 로 둔다
- 손맛 · 재미 판정
- 최종 밸런스 수치
- 플랫폼 인증 제출

### 에이전트 도구 (있으면 쓴다)

- 이 세션에 엔진 MCP(Unreal MCP · Unity MCP 등)가 연결돼 있으면 에디터 조작 · 자동 시험 실행에 쓴다. 없으면 엔진 명령줄(헤드리스 시험)로 하고, 그것도 안 되면 사람이 돌릴 명령을 알려 준다.
- 엔진 도구로 바꾼 에셋 · 씬 목록은 보고에 남긴다. 연결되지 않은 도구를 설치하라고 조르지 않는다.
