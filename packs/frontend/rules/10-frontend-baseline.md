## 프론트엔드 — 고치기 전 점검 (프레임워크 무관)

판단·금지만 둔다. 세부는 작업별 frontend 룰(on-demand)과 그 스택 팩 룰.

1. **있는 것을 먼저 찾는다** — 디자인 시스템·공용 컴포넌트·생성 API 클라이언트·URL 상태 유틸·포맷터·i18n. 있으면 그것만 쓴다. 새 UI 라이브러리·패키지는 묻고 들이고, 잠금파일의 주인인 관리자로만 추가한다. 화면의 모양 · 배치는 정본(프로토타입 · 화면설계서)이 먼저다: 디자인 시스템은 그 모양을 만드는 부품이고, 기본 목록 · 표 · 기존 화면 모양으로 바꾸지 않는다.
2. **생성물은 손대지 않는다** — 재생성으로만 바뀐다. 화면에서 HTTP 를 직접 부르지 않는다(공통 인증·오류 처리 우회).
3. **서버가 판정한다** — 검증·권한·합계·상태. 화면은 표시만 바꾸고, 권한 게이팅은 안내일 뿐 보안 경계가 아니다.
4. **시맨틱 HTML 먼저, ARIA 는 그다음** — 키보드로 다 되고, 포커스가 보이고, 모든 컨트롤에 이름이 있다.
5. **신뢰할 수 없는 값을 HTML·URL·코드로 넣지 않는다** — 텍스트로 넣는다. 번들에 비밀값을 두지 않는다.
6. **상태를 다 그린다** — 로딩·빈·오류·성공. 권한 없는 컨트롤은 숨기지 않고 비활성 + 이유. 확인창은 되돌릴 수 없는 동작에만.
7. **오류는 무슨 일인지와 어떻게 고치는지** — 원인 자리 가까이에, 사용자가 넣은 값은 지우지 않는다.
8. **상태마다 주인은 하나** — 화면 상태(페이지·정렬·검색·필터·탭)는 URL, 서버 데이터는 캐시. 서버 응답을 전역 스토어에 복사하지 않는다.
9. **사용자 문구·숫자·날짜** — i18n 이 있으면 문구를 하드코딩하지 않는다. 숫자·날짜는 공용 포맷터로, 식별자는 포맷하지 않는다.
10. **끝나면 검증한다** — 프로젝트의 lint·typecheck·test·build 를 돌리고, UI 변경은 실제 브라우저에서 키보드·좁은 폭까지 본다. 프로토타입이 있는 화면은 같은 폭으로 나란히 비교한다(screens 팩 「프로토타입대로 구현」). 못 돌린 것은 미검증으로 적는다.
