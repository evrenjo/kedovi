## 완료 전에 — 프로젝트의 명령으로

- 린트·타입 검사·테스트·빌드를 **프로젝트가 정한 명령**(패키지 스크립트·README·CI 설정)으로 돌린다. 고친 범위를 먼저, 끝나기 전 전체를 한 번. 빌드는 개발 서버에서 안 보이는 오류를 잡는다.
- 실패를 남긴 채 완료라고 하지 않는다. 원래 실패하던 것이면 그 사실을 적는다. 못 돌린 것은 **미검증**으로 적는다.
- 테스트를 통과시키려고 **단언을 약하게 하거나 테스트를 지우거나 건너뛰기 표시를 달지 않는다.** 테스트가 틀렸다고 보면 이유를 적고 묻는다.

## UI 를 바꿨으면 실제 브라우저에서

타입·단위 테스트는 화면이 맞는지를 보지 않는다.

- **정본(프로토타입 · 화면설계서)이 있는 화면**은 정본 요소 체크리스트(`kedovi screens inventory <화면 ID>`)의 요소마다 판정을 적고, 같은 폭(PC · 폰)으로 정본과 구현 스크린샷을 나란히 비교한다 (`kedovi screens compare <화면 ID>`, 백엔드 없이 e2e 픽스처로 `--mock`). 이유 없는 차이는 고친다. `kedovi screens checklist <화면 ID>` 가 통과하기 전에는 화면 작업이 완료가 아니다.
- 바꾼 흐름을 끝까지 한 번(생성·수정·삭제가 있으면 모두), **응답이 끝난 뒤** 판정한다(로딩 중 화면으로 "0건" 을 판정하지 않는다).
- 콘솔 오류 0, 실패한 네트워크 요청 없음.
- 키보드만으로 같은 흐름, 포커스가 보이고 가려지지 않는다.
- 좁은 폭(320px 또는 앱 최소 폭)·200% 확대·다크 모드(있으면).
- 데이터 모양을 바꿔 본다 — 0건·1건·많은 건, 긴 문자열, 권한이 다른 계정. 같은 데이터로만 반복한 통과는 커버리지가 아니다.

## 테스트를 쓸 때

- **프로젝트의 기존 테스트 도구·위치·명명을 따른다.** 새 테스트 도구는 묻고 들인다. 바꾼 코드의 테스트는 추가·갱신한다.
- 구현 세부(내부 state·함수 이름·CSS 클래스)가 아니라 **사용자가 보는 결과**를 확인한다.
- 요소는 **역할·접근 가능한 이름으로** 찾는다(role → label → text … 마지막이 test id). 역할로 못 찾으면 접근성 결함일 수 있다.
- 고정 시간 대기(`sleep`·`waitForTimeout`)를 넣지 않는다 — 조건을 기다리는 자동 재시도 단언으로.
- 테스트는 서로 독립(자기 데이터·저장소). 통제 못 하는 외부 서비스는 모킹.
- 상태별로 본다 — 로딩·재조회·빈·조회 실패·저장 실패(필드 / 시스템)·성공·권한 없음·경계 입력(입력·미입력·초과).
- 시각 회귀 기준 이미지는 의도한 변경일 때만 갱신한다. 변하는 부분(시각·난수·애니메이션)은 가린다.
