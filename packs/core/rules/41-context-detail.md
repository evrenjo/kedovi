## 컨텍스트 관리 상세

`AGENTS.md`(와 그것을 가져오는 `CLAUDE.md`)는 매 세션 통째로 로드된다. 한 줄을 더하면 모든 세션의 비용이고, 길어질수록 개별 규칙이 덜 지켜진다.

### 예산

- 모든 팩의 always 룰 + 레포 표 + 색인이 `AGENTS.md` 한 파일에 들어간다. Codex 는 이 파일을 `project_doc_max_bytes`(기본 32KB)에서 **자르고**, 잘린 뒤쪽 룰은 조용히 사라진다. `node bin/kit.js check` 가 한도를 검사한다.
- 팩 하나의 always 룰은 합계 6KB 안팎을 목표로 한다. 넘으면 새 룰을 넣지 말고 **강제 장치(린터·훅·CI)가 이미 막아 주는 룰**부터 on-demand·`docs/` 로 내린다.

### 새 규칙을 넣기 전에

1. 린터·포매터·pre-commit·검사 스크립트로 막을 수 있는가 → 장치로 만든다 (문서는 잊히고 장치는 안 잊힌다)
2. 모든 작업에 필요한 판단·금지인가 → always. 한 줄씩 "이 줄이 없으면 실수하는가" 를 묻고, 아니면 뺀다
3. 특정 작업에서만 필요한가 → on-demand. `when` 은 에이전트가 스스로 해당 여부를 판단할 수 있는 문장으로
4. 절차·예시·근거·이력인가 → 팩 `docs/` 또는 `handoffs/`

- **언제 추가하나** — 같은 실수가 두 번 나왔을 때, 리뷰에서 "이건 알았어야 했다" 가 나왔을 때, 같은 설명을 세션마다 반복할 때. 사용자의 교정이 기존 룰과 부딪히면 룰을 고치자고 제안한다.
- **무엇을 빼나** — 코드를 읽으면 알 수 있는 것(폴더 설명·의존성 목록), 언어의 일반 관례, "깨끗한 코드를 써라" 같은 자명한 말, 자주 바뀌는 값. 저장소 개요는 효과가 약하다는 연구가 있다.
- **복사하지 말고 가리킨다** — 버전·규칙 목록·개수를 룰에 베끼면 낡는다. 정본 파일(설정·스크립트·문서)의 경로를 적는다.
- 규칙은 검증할 수 있게 구체적으로 쓴다 ("테스트하라" 가 아니라 "커밋 전 `npm test`").
- 서로 부딪히는 규칙을 두지 않는다 — 추가할 때 같은 주제의 기존 룰을 찾아 합친다.
- 강조(🚫·**굵게**)는 아껴 쓴다. 모두 강조하면 아무것도 강조되지 않는다.
- 코어 룰의 근거 자료: `packs/core/docs/SOURCES.md`

### 참조는 실존만

- 죽은 참조는 "정본이 있다" 는 거짓 신호라 판단을 오염시킨다. 죽은 참조는 pre-commit 이 막는다.
- 옮기기 전에 누가 가리키는지 본다: `node packs/core/bin/rename-ref.js --check <경로>`
- 미리보기 → 적용: `node packs/core/bin/rename-ref.js <old> <new>` → `--apply` (참조 갱신 + git mv + kit sync + 검사). 손으로 `git mv` 하지 않는다. repo 문서까지는 `--repos`, 그 repo 에서 따로 커밋한다.
- 파일명만 적힌 곳은 자동으로 안 고친다 — 목록을 보고 문맥대로 직접 고친다. `handoffs/` 는 지난 사실의 기록이라 고치지 않는다.
- 일부러 없는 경로를 적는 자리는 자리표시자(`<루트>/…`)를 쓰거나 그 줄에 `refs:ignore` 를 적는다. 설치 서버 경로처럼 여러 줄이면 `<!-- refs:ignore-start -->` … `<!-- refs:ignore-end -->`, 문서 전체면 `<!-- refs:ignore-file -->`. 외부 주소 링크의 글자는 검사하지 않는다.
- 수동 검사: `node packs/core/bin/check-refs.js`

### 스크립트 위치 — "다른 개발자 PC 에도 있어야 하는가"

| | 팩 `bin/` (`packs/<팩>/bin/`) | `scripts/` |
|---|---|---|
| 성격 | 공용 도구 — 공유 자산을 관리·검사·생성 | 개인 1회용 |
| git | 추적 | 미추적 (`.gitignore`) |
| 룰·스킬·훅이 가리켜도 되나 | 된다 | **안 된다** — 남의 PC 에 없다. 의존하면 팩 `bin/` 으로 올린다 |

- 이 프로젝트에서만 쓰는 공용 도구는 `packs/project/bin/` 에 둔다 (킷 upgrade 가 `packs/project/` 는 건드리지 않는다).
- 도구가 만드는 큰 산출물(파일 수백 개 · 수 MB)은 다시 만들 수 있으면 `.gitignore` 에 넣고 각자 만든다. 만드는 명령을 그 도구를 가리키는 룰 · 스킬에 적는다. 다시 만들 수 없는 자료만 git 에 둔다 (기획 repo 가 있으면 거기).
- repo 안 임의 위치에 흩뿌리지 않는다. 버릴 산출물(캡처·덤프)은 OS 임시 폴더로, 끝나면 지운다.
- 문서에 개인 스크립트를 적을 때는 "(개인 스크립트 — git 미공유)" 라고 표시한다.

### 백업

지금은 필요 없지만 지우기 이른 파일은 가까운 `backup/` 폴더로 옮긴다. `backup/` 과 그 하위는 검색·인용·정본 판단 어디에도 쓰지 않는다.
