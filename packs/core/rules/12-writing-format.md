## 사람이 읽는 글 형식

**대상**: 사람이 읽는 글 전부. 제품 문서 · 기획 · 위키 · 작업 항목(이슈) · MR · 댓글 · 보고 · 주간보고 · 채팅 답변.
**제외**: AI 가 읽는 규칙 문서(AGENTS · CLAUDE · 룰 · 스킬 · 지시서). 그 프로젝트에 정한 틀(GitLab · GitHub 이슈 · MR 틀, 문서 관례)이 있으면 그것이 먼저다.

### 원칙

| 원칙 | 쓰는 법 |
|---|---|
| 두괄식 | 첫 줄 = 결론 · 요청. 배경 · 경위는 그 뒤 |
| 개조식 | 문장 대신 글머리. 끝은 명사형 · 「~함 · ~됨 · ~임」. 「~했습니다 · ~합니다」 로 늘이지 않는다 |
| 한 글머리 한 가지 | 한 줄에 사실 · 판단 하나. 둘 이상이면 나누거나 하위 글머리로. 길이 기준 {{ws:vars.writing.bulletMax}}자 (`vars.writing.bulletMax`) |
| 핵심만 굵게 | 굵게는 결론 · 요청 · 판정 낱말에만. 한 단락에 한두 곳 |
| 비교는 표 | 둘 이상을 견주거나 항목마다 같은 칸(상태 · 담당 · 날짜)이 있으면 표 |
| 인사말 없음 | 「안녕하세요 · 감사합니다 · 이상입니다 · 잘 부탁드립니다」 를 쓰지 않는다 |
| 빈칸 없음 | 틀의 `<…>` 자리표시자 · 빈 글머리 · 값이 빈 항목(`- 원인:`) · 빈 표 행 · 빈 절을 남기지 않는다. 해당 없으면 「없음」 · 「해당 없음」 |
| 이 PC 에만 있는 것 없음 | 보고 페이지 링크(`127.0.0.1`) · `.agents/` · 임시 폴더 경로 · worktree · 로컬 브랜치(`kedovi/…`) · push 안 한 커밋 · 에이전트 ID. 읽는 사람이 열 수 있는 것(MR · 이슈 · 문서 사이트 주소 · push 한 커밋)으로 바꾼다 |

개조식 예:

| 쓰지 않는다 | 대신 |
|---|---|
| 로그인 API 에서 토큰 만료 시 재발급을 하지 않고 있어서 사용자가 다시 로그인해야 하는 문제가 있었습니다. | - **토큰 만료 시 재발급 안 됨** → 다시 로그인 필요 |
| 원인을 확인해 보니 필터 조건이 빠져 있었고, 이를 추가하여 수정했습니다. 테스트도 통과했습니다. | - 원인: 필터 조건 빠짐<br>- 조치: 조건 추가<br>- 확인: 단위 시험 통과 |

### 보고 4단

1. **핵심 요약**: 결론 · 요청 한두 줄
2. **배경 · 현황**: 왜 · 지금 상태
3. **내용**: 안 · 결과 (표 먼저)
4. **다음 할 일 · 요청**: 누가 · 무엇을 · 언제. 없으면 「없음」

댓글 · 채팅처럼 짧은 글은 1 · 3 · 4 만.

### 문서별 틀

틀은 `kedovi draft template <형식>` 이 정본이다 (옮겨 적지 않고 매번 꺼내 쓴다).

| 형식 | 글 | 필수 절 |
|---|---|---|
| `task` | 작업 항목 (이슈) | 요약 · 할 일 · 완료 조건 |
| `bug` | 결함 (이슈) | 현상 · 재현 · 기대 / 실제 |
| `mr` | MR · PR 본문 | Summary |
| `done` | 완료 댓글 (조치 보고) | 결과 · 조치 · 확인 |
| `weekly` | 주간보고 | 요약 · 완료 · 진행 중 |
| `report` | 보고 · 위키 · 제안 · 보고 페이지(`kedovi report new`) | 핵심 요약 · 내용 · 다음 할 일 · 요청 |
| `plan` | 기획 문서 | 기획 repo 각 폴더의 `_template.md` 절 |

### 올리기 · 커밋 전 검사

- 올리기 전: `kedovi draft check --file <본문 파일> --type <형식>` (이슈 · 댓글은 `issue-check.js --type` 이 함께 본다). 걸린 것을 고친 뒤 미리보기를 보인다.
- 막는 곳: gitlab 팩 이슈 · MR 도구, `gh` · `glab` 이슈 · PR · MR 명령(훅), 기획 repo 커밋(pre-commit, 올리는 md 의 더한 줄 · 새 문서의 빠진 절). 위키 repo 를 쓰면 `workspace.json` repos 에 kind `docs` 로 두면 같은 커밋 검사를 받는다.
- 수준: `kedovi team-mode enforce draft off|warn|block` (기본 막기). 팀의 로컬 ID 모양은 `vars.writing.localIds` (정규식 목록)에 더한다.

### 예외 · 설정

- **확인 요청 글**(다른 사람에게 판단을 구하는 이슈 · MR · 코멘트)은 존댓말 문장으로 쓴다 (`core--11-confirm-request-tone`). 두괄식 · 표 · 근거는 같다.
- 개조식 · 서술식과 개조식에서 뺄 대상은 개인 지침 머리 「글 형식」(`kedovi prefs writing` · `writing-except`)이 이 룰보다 먼저다. 서술식이어도 두괄식 · 비교는 표 · 인사말 없음 · 빈칸 없음은 그대로.
