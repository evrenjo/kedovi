## 사람이 읽는 글 형식

**대상**: 사람이 읽는 글 전부. 채팅 답변, 제품 문서, 기획, 위키, 작업 항목(이슈), MR, 댓글, 보고, 주간보고, 환경 · 설정 파일 주석.
**제외**: AI 가 읽는 규칙 문서(AGENTS · CLAUDE · 룰 · 스킬 · 지시서). 그 프로젝트에 정한 틀(GitLab · GitHub 이슈 · MR 틀, 문서 관례)이 있으면 그것이 먼저다.

### 4대 원칙

| 원칙 | 쓰는 법 |
|---|---|
| 두괄식 | 첫 줄 = 결론 · 요청. 배경 · 경위 · 예외는 그 뒤. 절과 단락도 첫 문장에 핵심을 둔다. 절차 문장만 조건을 먼저 쓴다 (「운영에 올리려면 승인을 받는다」) |
| 개조식 | 문장 대신 글머리. 끝은 명사형 · 「~함 · ~됨 · ~임」. 순서가 있으면 번호. 한 줄에 사실 · 판단 하나, 길이 기준 {{ws:vars.writing.bulletMax}}자 |
| 간결성 | 한 문장에 정보 하나. 문장 {{ws:vars.writing.sentenceMax}}자 안. 수식어 · 같은 말 반복을 뺀다. 가운데점은 한 문장에 {{ws:vars.writing.dotMax}}개까지, 더 많으면 표나 하위 글머리. 괄호는 {{ws:vars.writing.parenMax}}자 안 |
| 가독성 | 내용이 드러나는 제목, 빈 줄로 나눈 묶음, 글머리는 두 단계까지. 단락 {{ws:vars.writing.paragraphMax}}자 안. 훑어도 구조가 보이게 쓴다 |

### 줄일 때 지킬 것

- 뜻이 사라질 만큼 줄이지 않는다. 행위 주체가 모호하면 주어를 쓴다.
- 명사를 셋 이상 잇지 않고 조사 · 서술어를 넣는다 (「일괄 공사 변경 협의」 → 「일괄 공사로 바꾸도록 협의」).
- 「적의 조치 요망」 같은 줄인 말투 대신 할 일을 쓴다 (「담당자가 오늘까지 권한을 회수함」).
- 번역 투를 피한다: 「~에 있어서」 → 「~에서」, 「~에 의해」 → 주어를 앞에, 「~에 대해서」 → 「~에」 · 「~을」.
- 과장 · 홍보 표현 대신 수치 · 사실을 쓴다.

### 공통 규칙

| 규칙 | 쓰는 법 |
|---|---|
| 핵심만 굵게 | 굵게는 결론 · 요청 · 판정 낱말에만. 한 단락에 한두 곳 |
| 비교는 표 | 둘 이상을 견주거나 항목마다 같은 칸(상태 · 담당 · 날짜)이 있으면 표 |
| 인사말 없음 | 「안녕하세요 · 감사합니다 · 이상입니다 · 잘 부탁드립니다」 를 쓰지 않는다 |
| 빈칸 없음 | 틀의 `<…>` 자리표시자 · 빈 글머리 · 값이 빈 항목(`- 원인:`) · 빈 표 행 · 빈 절을 남기지 않는다. 해당 없으면 「없음」 · 「해당 없음」 |
| 소스 코드 표현 없음 | 파일명 · 줄 번호 · 소스 경로 · 함수 · 클래스 · 변수 이름을 쓰지 않는다 (인용구 안도 같다). 기능 · 화면 · 동작 이름, 기획 ID, 이슈 · MR 번호로 쓴다. 독자가 직접 입력하는 명령 · 설정 키와 코드 블록의 명령 · 로그는 괜찮다 |
| 이 PC 에만 있는 것 없음 | 보고 페이지 링크(`127.0.0.1`) · `.agents/` · 임시 폴더 경로 · worktree · 로컬 브랜치(`kedovi/…`) · push 안 한 커밋 · 에이전트 ID. 읽는 사람이 열 수 있는 것(MR · 이슈 · 문서 사이트 주소 · push 한 커밋)으로 바꾼다 |

### 환경 · 설정 파일 주석

대상: `.env` 계열, `.conf`, `.ini`, `.properties`, `.toml`, `.yml`, `.yaml`.

- 키 바로 윗줄에 쓴다. 첫 줄 = 이 값이 무엇인지.
- 다음 줄에 필요한 것만: 허용값, 기본값, 단위, 바꾸면 생기는 영향.
- 한 줄에 한 문장. 관련 키는 빈 줄과 구획 제목으로 묶는다.
- `.env` · `.properties` 는 값 뒤에 주석을 달지 않는다. 도구에 따라 값의 일부로 읽힌다.
- `.env.example` 은 모든 키에 설명을 둔다. 실제 비밀값은 주석에도 쓰지 않는다.
- 변경 경위 · 대화 맥락은 쓰지 않는다. 지금 뜻만 적는다.

```
# 결제 API 요청 제한 시간 (단위: 초)
# 기본값 30. 낮추면 느린 결제가 실패 처리됨
PAYMENT_TIMEOUT=30
```

코드 주석은 다르다. 코드가 말하지 않는 이유 · 제약 · 함정만 쓴다 (`core--28-work-detail`).

개조식 예:

| 쓰지 않는다 | 대신 |
|---|---|
| 로그인 API 에서 토큰 만료 시 재발급을 하지 않고 있어서 사용자가 다시 로그인해야 하는 문제가 있었습니다. | - **토큰 만료 시 재발급 안 됨** → 다시 로그인 필요 |
| 원인을 확인해 보니 필터 조건이 빠져 있었고, 이를 추가하여 수정했습니다. 테스트도 통과했습니다. | - 원인: 필터 조건 빠짐<br>- 조치: 조건 추가<br>- 확인: 단위 시험 통과 |

### 보고 4단

1. **핵심 요약**: 결론 · 요청 한두 줄
2. **배경 · 현황**: 왜 · 지금 상태
3. **내용**: 안 · 결과 (표 먼저)
4. **다음 할 일 · 요청**: 누가 · 무엇을 · 언제. 없으면 「없음」

댓글 · 채팅처럼 짧은 글은 1 · 3 · 4 만.

### 문서별 틀

틀은 `kedovi draft template <형식>` 이 정본이다 (옮겨 적지 않고 매번 꺼내 쓴다).

| 형식 | 글 | 필수 절 |
|---|---|---|
| `task` | 작업 항목 (이슈) | 요약 · 할 일 · 완료 조건 |
| `bug` | 결함 (이슈) | 현상 · 재현 · 기대 / 실제 |
| `mr` | MR · PR 본문 | Summary |
| `done` | 완료 댓글 (조치 보고) | 결과 · 조치 · 확인 |
| `weekly` | 주간보고 | 요약 · 완료 · 진행 중 |
| `report` | 보고 · 위키 · 제안 · 보고 페이지(`kedovi report new`) | 핵심 요약 · 내용 · 다음 할 일 · 요청 |
| `plan` | 기획 문서 | 기획 repo 각 폴더의 `_template.md` 절 |

### 올리기 · 커밋 전 검사

- 올리기 전: `kedovi draft check --file <본문 파일> --type <형식>` (이슈 · 댓글은 `issue-check.js --type` 이 함께 본다). 걸린 것을 고친 뒤 미리보기를 보인다.
- 막는 곳: gitlab 팩 이슈 · MR 도구, `gh` · `glab` 이슈 · PR · MR 명령(훅), 기획 repo 커밋(pre-commit, 올리는 md 의 더한 줄 · 새 문서의 빠진 절). 위키 repo 를 쓰면 `workspace.json` repos 에 kind `docs` 로 두면 같은 커밋 검사를 받는다.
- 코드 표현: 파일:줄 · 소스 파일명 · 소스 경로 · 함수 호출은 막고, 클래스 · 변수 이름 모양은 알린다. 기획 repo 커밋 · 문서 사이트 점검은 알리기만 하고, 위키 repo 커밋은 막는다. 꼭 필요한 이름은 `vars.writing.codeAllow` (정규식 목록)에 더한다.
- 쉬운 글: 긴 문장 · 가운데점 나열 · 긴 괄호 · 긴 단락 · 번역 투 · 줄인 말투 · 인사말은 알리기만 한다. 기준은 `vars.writing.sentenceMax` · `dotMax` · `parenMax` · `paragraphMax`.
- 설정 파일 주석: `kedovi draft config --file <파일>`. 에이전트가 설정 파일을 고치면 훅이 같은 검사를 알린다. 막지 않고 값은 찍지 않는다.
- 수준: `kedovi team-mode enforce draft off|warn|block` (기본 막기). 팀의 로컬 ID 모양은 `vars.writing.localIds` (정규식 목록)에 더한다.

### 예외 · 설정

- **확인 요청 글**(다른 사람에게 판단을 구하는 이슈 · MR · 코멘트)은 존댓말 문장으로 쓴다 (`core--11-confirm-request-tone`). 두괄식 · 표 · 근거는 같다.
- 개조식 · 서술식과 개조식에서 뺄 대상은 개인 지침 머리 「글 형식」(`kedovi prefs writing` · `writing-except`)이 이 룰보다 먼저다. 서술식이어도 두괄식 · 간결성 · 가독성 · 비교는 표 · 인사말 없음 · 빈칸 없음은 그대로.
