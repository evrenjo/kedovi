## 역할 에이전트 쓰기

**합의된 작업 안에서 일을 나눌 때는** 묻지 않고 역할 에이전트(분석·설계·구현·테스트·리뷰·문서)를 불러 나누고, 끝나면 정리한다. 목적은 메인 대화 context 를 아껴 오래 일하는 것이다. 역할·순서·넘겨주기는 `team` 스킬.
"묻지 않는다" 는 일을 나누는 방법에만 해당한다. 단계 전환(분석 → 기획 → 설계 → 구축)과 그 단계의 진행 방식은 상시 룰 「커뮤니케이션」대로 사용자와 정한 뒤 시작한다.

- **부른다**: 많이 읽어야 하는 조사(결론만 받는다) · 서로 독립인 작업을 나란히 · 구현과 다른 눈의 검토.
- **부르지 않는다**: 이미 읽은 내용 · 앞뒤가 강하게 묶인 일. 지시하고 다시 읽는 비용이 더 크다.
- **메인은 대화 전담** (세션 시작 줄의 「메인 방식」): repo 파일 수정은 한두 줄이어도 에이전트에 맡기고(작은 수정은 지금 대화를 이어받는 대화 사본, 나머지는 역할 에이전트), 무엇을 맡겼는지 한 줄 보고한 뒤 차례를 끝낸다. 오래 걸리는 명령도 백그라운드로. 메인이 붙들고 있으면 그 사이 사용자 메시지를 놓친다. 「직접 작업도 한다」 면 한두 파일 수정은 메인이.
  > Codex: 메인이 한두 파일 수정을 직접 한다 (위 항목은 Claude Code).
- **작업 중 받은 메시지**: 일하는 사이 사용자 메시지가 끼어 들면 다음 글에서 받았다고 한 줄 알리고, 끝 보고에 `작업 중 받은 메시지: <요약> → 처리함 | 할 일로 남김(이유)` 줄을 적는다.
- **적게**: 이 PC 의 상한(개인 지침의 「역할 에이전트 상한」) 안에서. 같은 역할이 다시 필요하면 새로 부르지 말고 앞 에이전트에게 이어서 맡긴다. 상한을 넘겨야 하면 이유와 함께 사용자에게 묻는다.
- **짧게 받는다**: 보고는 결론 · 근거(`파일:라인`) · 추정·미확인만. 파일 원문을 통째로 받지 않는다.
- **정리한다**: 사용자에게 보고할 때 **일하는 중인** 에이전트·위임 작업이 0 이어야 한다. 일을 마치고 대기(idle) 중인 에이전트는 리뷰 지적을 고치게 다시 부를 수 있으니 남겨 두고, 리뷰 뒤 수정까지 끝나면 종료한다. 다시 맡길 일이 정해져 있지 않으면 종료한다. 에이전트 · 백그라운드 작업이 남은 채 턴을 끝내면 답변 끝에 `지금 도는 것: … · 예상 종료: … · 사용자가 할 일: 있음(무엇) | 없음` 한 줄을 적는다 (대기 중인 에이전트는 일하는 것으로 적지 않는다).
- **독립 단위가 2개 이상이면 3층**: 메인 → 작업 리더(`lead`, 단위마다, 서브에이전트) → 팀원. 상한은 개인 지침의 리더 · 리더당 팀원 수, 같은 repo 는 `kedovi worktree` (`team` 스킬 「작업 리더」).
- **실행 방식**: 세션 시작 줄의 「역할 에이전트 실행 방식」(팀 모드 · 서브에이전트) 판정을 따르고, 작업 시작 때 한 줄로 알린다 (`team` 스킬).
