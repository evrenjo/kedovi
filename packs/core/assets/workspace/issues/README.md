# 이슈

이슈(결함 · 요청 · 할 일)를 관리하는 곳. 원격이 정해지면 원격의 이슈가 정본이다.

| 상황 | 관리 위치 | ID 꼴 |
|---|---|---|
| 원격 없음 | 이 폴더: 이슈 하나에 한 파일 (번호-제목.md) | ISSUE-001 |
| GitLab | 작업 항목 · 이슈 | #123 (다른 프로젝트면 그룹/프로젝트#123) |
| GitHub | 이슈 | #123 (다른 repo 면 계정/repo#123) |
| 외부 PMS | 아래 「외부 PMS」 에 적은 곳 | 그 시스템의 꼴 |

## 이슈 ID 거는 법

| 자리 | 거는 법 |
|---|---|
| 사람 문서 | 근거 인용구나 표의 칸에 ID 를 적는다. 예: 「> 근거: #123」 |
| 커밋 · MR | 제목이나 본문에 ID 를 적는다. GitLab · GitHub 는 #123 을 그 이슈로 잇는다 |
| 기능 문서 | 기능의 단계를 바꾼 이슈는 본문에 그 기능 번호를 적는다 |

## 이 폴더의 이슈 파일

원격이 없을 때만 쓴다. 파일 머리 줄에는 상태와 종류, 담당, 관련 기능 번호를 적는다.

| 칸 | 값 |
|---|---|
| 상태 | 열림 · 처리 중 · 닫힘 |
| 종류 | 결함 · 요청 · 할 일 |

원격을 붙이면 열린 이슈를 원격으로 옮기고 이 폴더에는 이 README 만 남긴다.
