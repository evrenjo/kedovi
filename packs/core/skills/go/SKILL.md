# go — 작업 시작

코드를 고치기 **전에** 상황을 맞추고 계획을 합의한다. 계획 없이 편집부터 하지 않는다.

## 1. 맥락 맞추기 (짧게)

- 본인 `handoffs/{id}/LATEST.md` · `handoffs/{id}/TODO.md` 를 읽는다 (`{id}` = 루트 `git config user.name`). 요청이 진행 중 작업과 이어지는지·겹치는지 본다.
- repo 상태: 세션 시작 훅이 알린 뒤처짐·미커밋·드리프트가 있으면 먼저 정리할지 묻는다. 훅 출력이 없으면 `node packs/core/bin/repo-activity.js` 로 본다.
- 작업 대상 repo 의 `AGENTS.md` 색인 표("작업별 필수 참고")에서 해당하는 on-demand 룰을 **먼저 읽는다**.

## 2. 요청 다시 말하기

사용자 요청을 한두 문장으로 다시 적는다 — 무엇을, 어디까지, 완료 기준은 무엇인지. 모호한 점이 **사용자만 정할 수 있는 것**이면 선택지 질문(권장안 첫째)으로 묻고, 코드·문서로 확인되는 것은 직접 확인한다.

## 3. 조사 → 계획 제시 (편집 전)

코드와 문서를 함께 보고(문서는 낡았을 수 있으니 코드로 재확인하고, 다르면 판정을 보인다: 정본이 맞음 · 구현이 맞음 · 판단 불가) 아래 칸을 채워 `착수 전 확인:` 머리말 아래 제시한다. 코드 repo 를 처음 고칠 때 이 머리말이 이번 요청 · 바로 앞 요청의 답변에 없으면 훅이 알린다(`kedovi team-mode enforce plan`). 오타 · 한두 줄 같은 단순 수정은 `착수 전 확인: 단순 수정 (이유)` 한 줄로 된다.

| 칸 | 내용 |
|---|---|
| **영향 범위** | 전수 검색 결과 — 코드·주석·문서·설정·데이터(시드·스키마)·다른 repo. 기존 동작·계약을 바꾸면 `.agents/rules/core--30-change-impact.md` 체크리스트대로 |
| **방식** | 제대로 하는 안(권장: 요구사항 전체 + 사이드이펙트 처리)과 더 간단한 안을 나란히 보인다. 간단한 안에는 빠지는 것(못 채우는 요구 · 남는 위험 · 나중에 드는 일)을 적는다. 간단한 안이 빠뜨리는 것이 없으면 하나만 |
| **할 일** | 파일 단위 목록 (repo 별) |
| **검증 계획** | 무엇을·어떻게·무엇으로 증명하는지 — 빌드/타입체크 명령, 쿼리, 화면 실행. 축이 다른 5케이스 이상 |
| **안 할 것** | 요청과 관계없어 범위 밖으로 두는 것과 그 이유 (요청한 요구 · 그 사이드이펙트는 여기에 두지 않는다) |
| **화면 정본** | 화면을 만들거나 고치면 화면 ID 마다 `kedovi screens inventory <화면 ID>` 결과 한 줄: 정본 경로 · 판정 · 요소 수 · 체크리스트 경로 · 데이터 원천이 없는 요소 (screens 팩). 둘 다 있고 다르거나 둘 다 없으면 여기서 묻는다 |
| **공유 상태 · 구조 결정** | 여러 화면·프로세스가 같이 쓰는 상태(캐시·창 사이 동기화·서버 상태)를 건드리면 정본이 어디고 어떻게 맞출지 먼저 정한다. 땜질로 맞추지 않는다 |
| **시간 예산** | 예상 시간. 착수할 때 `node packs/core/bin/budget.js start "<작업>" <시간>`, 끝나면 `done`. 1.5배를 넘으면 훅이 알리고 계속할지 묻게 한다. 예산은 줄이려는 기준이 아니다: 넘어도 범위를 줄이자고 먼저 권하지 않는다 |

- 검증 계획이 없는 변경은 시작하지 않는다 (버그 수정·리팩토링 포함).
- 세션 중간에 온 새 기능 요청에도 이 단계를 쓴다 (첫 요청만이 아니다).
- 사용자가 계획을 확인한 뒤 착수한다. 이미 "바로 진행" 을 명시했으면 계획을 보여 주고 이어서 진행한다.
- 산출물이 코드가 아니라 **논의가 필요한 문서**(요구사항·범위·설계·결정표)면 위 네 칸 대신 **논의할 항목 · 순서 · 산출물 형태**를 제안해 합의한다. 초안을 먼저 쓰지 않고, 결정 질문은 앞 답에 따라 순서대로 나눠 묻는다.

## 4. 진행 · 마무리

- 사용자가 고른 범위는 끝까지 간다. 못 한 것은 "안 함" 이 아니라 "사용자 결정으로 보류" 라고 적는다.
- 끝나면 검증표(`대상 / 케이스 / 방법 / 기대 / 실제 / 판정`)로 보고한다. 못 채운 칸은 "미검증".
- 화면을 바꿨으면 `kedovi screens checklist <화면 ID>` 가 통과해야 완료다. 판정 없는 요소 · 비교 미실행이 남으면 완료로 보고하지 않고 알린다. 보고에 `--md` 표를 싣는다.
- 보고 직전에 스스로 점검한다 — 추론으로 넘긴 판정, 안 본 소비처, 옛 이름이 남은 주석·문서, 실행 안 한 검증, 결정 대기 항목을 임의로 진행했는지, 파일 밖 전파(데이터·설정·다른 repo)가 필요한지. 걸리면 "넘어가려던 것" 으로 먼저 밝힌다.
- 커밋·푸시는 사용자가 요청할 때만.
