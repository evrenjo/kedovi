# debug-trace: 실행 흐름 디버깅 페이지

`kedovi trace` 가 기록 · 페이지를 만든다. 이 스킬은 무엇을 어떻게 돌릴지 정하는 순서다. 지금은 JVM(Java · Kotlin, Gradle · Maven)만 된다. 다른 언어면 그렇다고 알리고 멈춘다.

## 1. 대상 찾기

| 사용자가 말한 것 | 찾는 것 |
|---|---|
| API (`POST /api/orders` · 「주문 API」) | 그 경로를 받는 컨트롤러 메서드 (`@*Mapping` · 라우터) |
| 함수 · 서비스 (`OrderService.place`) | 그 메서드와 부르는 쪽 |
| 배치 · 스케줄 작업 | 작업 클래스의 실행 메서드 (`run` · `execute` · `@Scheduled`) |

여럿이면 후보를 보여 주고 하나를 묻는다. 대상이 든 repo 를 정한다 (`workspace.json` repos).

## 2. 실행 방식 고르기

| 방식 | 언제 | 명령 |
|---|---|---|
| **테스트** (기본) | 언제나. 같은 입력으로 다시 볼 수 있다. 함수 · 배치는 이것만 | `kedovi trace run --test <테스트 클래스>#<메서드> [--repo <이름>]` |
| **로컬 서버 요청** | 사용자가 「로컬 데이터로」 · 「실제 서버로」 라고 할 때 (API 만) | `kedovi trace run --request "<METHOD> http://localhost:<포트>/<경로>" [--data '<본문>'] [-H 'K: V'] [--repo <이름>]` |

- 테스트: 대상을 부르는 기존 테스트가 있으면 그것을 쓴다. 없으면 기록용 테스트를 새로 만든다.
  - API 는 `@SpringBootTest` + `@AutoConfigureMockMvc`, 프로젝트에 맞는 요청 본문 · 테스트 데이터를 쓴다. 함수 · 배치는 그 빈을 주입해 한 번 부른다.
  - 파일은 그 repo 의 테스트 폴더에 `<대상>TraceTest` 로 두고, 만든 것을 보고에 적는다. 커밋할지는 사용자에게 묻는다.
- 로컬 서버: 킷이 `bootRun`(Maven 은 `spring-boot:run`)을 디버그 포트와 함께 띄우고, 요청 한 번을 기록한 뒤 서버를 끈다.
  - 이미 디버그 포트로 띄운 서버가 있으면 `--attach <디버그 포트>` 를 쓴다.
  - 주소는 localhost 만 된다. 운영 · 개발 서버에는 붙지 않는다.
  - 로그인이 필요한 API 는 헤더(`-H 'Authorization: …'`)를 사용자에게 받는다. 값은 채팅 · 보고에 적지 않는다.

## 3. 돌리고 보고하기

1. 명령을 돌린다. 처음에는 빌드 · 의존성 받기로 몇 분 걸릴 수 있다. 기록 중에는 평소보다 느리다.
2. 출력의 「기록: 호출 · 줄 · SQL · 예외」 와 `링크:` 를 확인한다. 경고(⚠)가 있으면 이유를 본다:

   | 경고 | 할 일 |
   |---|---|
   | 시작 메서드가 실행되지 않음 | 테스트 이름 · 메서드, `@Disabled` 확인 |
   | 테스트 실패 | 기록은 실패 지점까지 있다. 실패 자체가 보고 대상인지 사용자에게 알린다 |
   | 단계 상한 | 대상이 너무 크다. `--max-steps` 를 올리거나 더 좁은 테스트로 |
   | Maven: SQL 은 pom 에… | SQL 없이도 흐름 · 값은 보인다. SQL 까지 보려면 pom 에 test 범위로 `datasource-proxy-spring-boot-starter` 를 넣을지 묻는다 |

3. 채팅에는 결론 1줄 + 흐름 요약 3~5줄(예: 필터 → 컨트롤러 → 서비스 → 저장소, 눈에 띄는 값 변화 · SQL · 예외) + `자세히: <링크>`.

- 기록 대상은 repo 의 기준 패키지(소스의 공통 패키지)와 테스트 패키지다. 다르면 `--include com.a,com.b`.
- 반복문은 줄마다 30회까지 값을 남기고 나머지는 횟수만 센다 (`--max-hits`).
- SQL 을 빼려면 `--sql off`.
- 지난 기록: `kedovi trace list` · `kedovi trace open [파일]`.

## 하지 않는다

- 운영 · 개발 · 공유 DB 에 붙은 서버를 기록하지 않는다. 로컬 · 테스트 DB 만 쓴다.
- 기록 파일(`.agents/traces/`)을 커밋하거나 밖으로 보내지 않는다. 실제 데이터가 들어 있다.
- 기록하려고 프로젝트의 빌드 파일 · 운영 코드를 고치지 않는다. 고칠 수 있는 것은 기록용 테스트 파일뿐이다.
