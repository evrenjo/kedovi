# screen-audit: 화면 품질 전체 점검

화면마다 품질 점검표를 맞추고, 자동 측정을 돌리고, 남은 필수 항목을 표로 보이고 고칠 순서를 제안한다. 화면 하나만이면 `kedovi screens quality <화면 ID>` 로 충분하다.

## 1. 준비 (처음 한 번)

| 확인 | 방법 |
|---|---|
| 수준 | `kedovi screens quality-level` 로 지금 값을 보이고 맞는지 묻는다 (공공 사업 · 일반 서비스 · 사내 도구). 바꾸면 `kedovi screens quality-level <값>` |
| 화면 목록 | `kedovi screens locate` 로 화면 ID 를 찾는지 본다. 못 찾으면 위치를 먼저 정한다 |
| 구현 주소 | 진입 파일의 `@spec <화면 ID>` · `@route` 가 있는지, 개발 서버가 떠 있는지. 백엔드 없이 하려면 목 픽스처(`--mock`) |
| 도구 | Playwright 브라우저 3종(`npx playwright install chromium firefox webkit`) · axe-core(`npm i -g axe-core`). 없으면 그 항목은 「미실행」 으로 남는다고 알린다 |

설치 · 서버 기동은 사용자 확인 뒤에 한다.

## 2. 점검

1. 현황: `kedovi screens audit` (점검표가 없는 화면은 만든다. 측정은 안 함).
2. 측정: `kedovi screens audit --run` (화면마다 자동 측정, 화면 수 × 1~2분). 설계 단계(구현 전)면 `--design` 으로 정본을 잰다.
3. 화면마다 남은 필수 항목 가운데 사람이 볼 것(문구 · 낭독기 · 대화상자 · 되돌리기 등)은 직접 확인하고 점검표 판정 칸에 적는다. 자동 측정이 「확인 필요」 로 남긴 것은 스크린샷(`.agents/screens/<화면 ID>/quality/`)을 보고 판정한다.

## 3. 보고 · 고칠 순서

- 표: 화면 · 필수 통과 · 실패 · 판정 없음 · 권장 남음 (`kedovi screens audit` 결과 그대로).
- 실패를 원인별로 묶는다 (공통 컴포넌트 · 토큰 하나로 여러 화면이 실패하면 그것부터). 화면마다 고치지 말고 공통 원인을 먼저 고칠지 묻는다.
- 고칠 것은 작업 기록 · 이슈로 남기고, 이번에 고치지 않는 것은 `예외 (결정 ID)` 로 판정에 남긴다 (결정 없이 넘기지 않는다).
- 사용성 평가 결과서가 없으면 `kedovi screens usability` 로 뼈대를 만들고 다음 마일스톤에 평가하자고 권한다.
