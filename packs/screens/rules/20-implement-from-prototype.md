## 화면 구현: 정본 · 요소 체크리스트

화면을 만들거나 고치기 **전에** 화면 ID 마다 `kedovi screens inventory <화면 ID>` 로 정본을 정하고 요소 체크리스트를 만든다. 판정과 체크리스트 경로를 착수 전 확인에 한 줄로 적는다.

| 있는 것 | 정본 |
|---|---|
| 프로토타입 (화면설계서 유무와 상관없이) | 프로토타입: 구성 · 스타일 · 상태 모양 |
| 화면설계서만 | 화면설계서 장 |
| 둘 다, 요소가 다름 (끝 코드 3) | 진행하지 않는다. 다른 점 표를 보이고 어느 쪽이 맞는지 묻고, 틀린 쪽 문서를 갱신 대상으로 결정 기록에 남긴다 |
| 둘 다 없음 (끝 코드 3) | 선택지로 묻는다: (권장) 프로토타입 · 화면설계를 먼저 만들고 확인한 뒤 구현 · 기능 명세대로 구현하고 화면은 디자인 시스템 기본형 (빠지는 것: 화면 확인 없이 만든 배치는 다시 고칠 가능성) |

- **착수 전**: 체크리스트(`handoffs/<나>/screens/<화면 ID>.md`)의 데이터 원천을 채우고 `kedovi screens checklist <화면 ID> --start`. 도구가 놓친 요소는 정본을 열어 더한다. **원천이 없어 못 만드는 요소는 착수 전에 사용자에게 알린다** (구현 뒤 차이표로만 알리지 않는다).
- **따를 것**: 영역 배치 · 타일 · 카드 머리(아이콘 · 제목 · 동작) · 상태 칩과 색 · 막대 · 그래프 · 간격 · 빈 값 · 오류 · 로딩 모양. 디자인 시스템 기본 목록 · 표로 바꾸지 않고, 같은 모양을 공용 컴포넌트로 만든다.
- **완료 전**: 모든 요소에 판정(`구현` · `다름 (이유)` · `뺌 (결정 ID)`)을 적고, 같은 폭(PC · 폰) 비교를 찍는다: `kedovi screens compare <화면 ID>` (진입점 `@spec` 줄의 `@route`, 백엔드 없이 `--mock <픽스처>`). `kedovi screens checklist <화면 ID>` 가 통과해야 완료다. 판정 없는 요소가 남았거나 비교가 「미실행」 이면 완료로 보고하지 않고 사용자에게 알린다 (대체 캡처는 무엇으로 했는지 밝힌다).
- 완료 보고 · MR 본문에 `kedovi screens checklist <화면 ID> --md` 표를 싣는다. 리뷰를 맡기면 지시서에 `kedovi screens review <화면 ID>` 블록을 넣는다 (`kedovi delegate` 는 저절로).
- 정본이 틀려 보이면 구현에서 바꾸지 않고 기획 쪽에 묻는다 (결정 기록).
