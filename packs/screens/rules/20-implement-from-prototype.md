## 화면 구현: 정본 · 요소 체크리스트

화면을 만들거나 고치기 **전에** 화면 ID 마다 `kedovi screens inventory <화면 ID>` 로 정본을 정하고 요소 체크리스트를 만든다. 판정과 체크리스트 경로를 착수 전 확인에 한 줄로 적는다. 체크리스트 없이 정본 있는 화면 진입 파일을 고치면 훅이 막는다 (`enforce screens`).

| 있는 것 | 정본 |
|---|---|
| 프로토타입 (화면설계서 유무와 상관없이) | 프로토타입: 구성 · 배치 · 스타일 · 상태 모양 |
| 화면설계서만 | 화면설계서 장 |
| 둘 다, 요소가 다름 (끝 코드 3) | 진행하지 않는다. 다른 점 표를 보이고 어느 쪽이 맞는지 묻고, 틀린 쪽 문서를 갱신 대상으로 결정 기록에 남긴다 |
| 둘 다 없음 (끝 코드 3) | 먼저 `kedovi screens locate` 로 위치 설정을 본다 (기획 repo 화면 폴더가 `30-screens` 가 아니거나 한 페이지 앱 프로토타입이면 `--dir` · `--prototype "<파일>#{id}"`). 정말 없으면 선택지로 묻는다: (권장) 프로토타입 · 화면설계를 먼저 만들고 확인한 뒤 구현 · 기능 명세대로 구현하고 화면은 디자인 시스템 기본형 (빠지는 것: 화면 확인 없이 만든 배치는 다시 고칠 가능성) |

- **우선순위**: 화면의 모양 · 배치는 정본이 디자인 시스템 · 기존 화면 관례보다 먼저다. 디자인 시스템 · 공용 컴포넌트는 그 모양을 만드는 부품으로 쓰고, 기본 목록 · 표 · 기존 화면 모양으로 바꾸지 않는다. 같은 모양이 여러 화면에 나오면 공용 컴포넌트로 만든다.
- **착수 전**: 체크리스트(`handoffs/<나>/screens/<화면 ID>.md`)의 데이터 원천을 채우고 `kedovi screens checklist <화면 ID> --start`. 도구가 놓친 요소는 정본을 열어 더한다. **원천이 없거나 API 계약이 정본보다 좁아 못 만드는 요소는 착수 전에 사용자에게 알리고 정한다** (정본대로 맞춤 · 계약을 넓힘 · 정본을 고침). 구현 뒤 차이표로만 알리지 않는다.
- **따를 것**: 영역 배치(어느 영역이 옆 · 아래인지) · 타일 · 카드 머리(아이콘 · 제목 · 동작) · 상태 칩과 색 · 막대 · 그래프 · 간격 · 빈 값 · 오류 · 로딩 모양.
- **완료 전**: 모든 요소에 판정을 적는다: `구현` · `다름 (이유)` · `뺌 (결정 ID)` · `보류 (후속: <작업 기록 · 이슈>)`. 이유가 계약 · 데이터 원천 · 범위면 구현 쪽이 정할 일이 아니다: 사용자 결정의 ID 를 함께 적는다 (없으면 checklist 가 통과시키지 않는다). 보류는 후속 위치(작업 기록 「완료 조건」 · 이슈)에 그 요소가 있어야 한다.
- 같은 폭(PC · 폰) 비교와 배치 대조를 찍는다: `kedovi screens compare <화면 ID>` (진입점 `@spec` 줄의 `@route`, 백엔드 없이 `--mock <픽스처>`). 정본에서 옆이던 영역이 아래로 가는 등 배치 차이는 체크리스트 「배치」 줄로 들어가 판정이 필요하다. `kedovi screens checklist <화면 ID>` 가 통과해야 완료다. 비교를 못 돌리면 사용자에게 알리고, 확인받은 대체 방법을 「- 비교: 대체: … (사용자 확인 <날짜>)」 로 적는다.
- 완료 보고 · MR 본문에 `kedovi screens checklist <화면 ID> --md` 표를 싣는다. 구현 · 리뷰를 맡기면 지시서에 `kedovi screens review <화면 ID> [--implement]` 블록을 넣는다 (`kedovi delegate` 는 저절로).
- 정본이 틀려 보이면 구현에서 바꾸지 않고 기획 쪽에 묻는다 (결정 기록).
