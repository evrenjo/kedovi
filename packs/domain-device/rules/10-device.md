## 장치: 명세 단위 · 검증 단계 · 사람 관문

### 명세 단위

- 기능 문서 = 요구사항 단위. 요구마다 위험(`HAZ-번호`) · 위험 대책(`RC-번호`) · 인터페이스(`IF-번호`) · 대상 보드 판(`HW-번호`)을 잇는다 (`docs-site/기능/_template.md`).
- 요구마다 펌웨어 · 앱 · 클라우드 중 누구 몫인지 적는다. 한 기능이 여럿에 걸치면 몫마다 FN 을 나눈다.
- BLE 통신 표(GATT 서비스 · 특성)와 메시지 형식은 인터페이스 명세로 남긴다 (AsyncAPI 파일을 코드 repo 에 두면 문서 사이트가 채널 표로 보여 준다).

### 코딩 규칙 · 예산

- 프로젝트가 정한 규칙 집합(MISRA C · CERT C 등)과 정적 분석 도구를 먼저 찾아 따른다. 정한 것이 없으면 정하자고 제안한다. 규칙 예외는 결정 문서로 남긴다.
- SDK 판 · 플래시 · RAM · 전력 예산은 펌웨어 · 전력 예산 문서가 정본이다. 바꾼 코드가 예산을 넘으면 완료가 아니다.
- 동적 메모리 · 막는 호출(blocking) · 인터럽트 안 긴 처리는 프로젝트 규칙이 허락할 때만 쓴다.

### 검증 단계 (AI 구현 뒤)

| 단계 | 하는 일 | 남기는 곳 |
|---|---|---|
| 정적 분석 | MISRA · CERT 검사 | 기능 문서 검증 표 (단계 · 결과 · 어디서) |
| 단위 | 호스트에서 단위 시험 | 같은 표 |
| 에뮬레이터 | Renode · Wokwi 같은 에뮬레이터에서 펌웨어 실행 | 같은 표 (에뮬레이터 이름 · 판) |
| HIL | 실제 보드에서 시험 · 전력 측정 | 같은 표 (보드 판 `HW-번호`) + HIL 문서 |

- **컴파일 통과만으로 완료가 아니다.** 돌리지 못한 단계는 「아직」 으로 두고 기능을 완료로 넘기지 않는다.
- 어디서 칸에는 보드 판 · 펌웨어 판 · 측정 장비처럼 다시 돌릴 수 있는 정보를 적는다.

### 사람 관문: 멈추고 묻는다

아래는 에이전트가 하지 않는다. 할 일 · 명령 · 근거를 보여 주고 사람 확인을 요청한 뒤 기다린다.

- 하드웨어 기동: 새 보드 판에 처음 굽기 · 전원 넣기
- 실제 보드에 굽기(flash) · 부트로더 · 퓨즈 · 보안 키 쓰기
- 전력 · 전파 시험 판정, 전파 출력 설정 바꾸기
- 안전 검토 (위험 · 대책 확정)
- 인증 (FCC · CE · 블루투스, 건강 기능이면 의료 규격) 제출 · 판정

### 에이전트 도구 (있으면 쓴다)

- 이 세션에 장치 MCP(Nordic nRF Connect MCP · Wokwi MCP 등)가 연결돼 있으면 빌드 · 에뮬레이터 실행 · 로그 읽기에 쓴다. 없으면 SDK 명령줄 · Renode 로 하고, 그것도 안 되면 사람이 돌릴 명령을 알려 준다.
- 굽기 · 전원 제어 도구가 있어도 위 사람 관문은 그대로 지킨다.
