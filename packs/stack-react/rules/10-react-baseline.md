## React 구현 기본 규약

frontend 레이어 원칙 위에 React 로 구현할 때의 판단·금지만 둔다. 절차·예시는 stack-react 의 작업별 룰.

- **서버 상태는 TanStack Query, 클라이언트 전역 상태는 스토어 하나**(Zustand 등). 서버 응답을 전역 스토어에 복사하지 않는다.
- **생성된 쿼리 옵션·mutation 옵션만 쓴다** (`getXxxOptions(...)` · `xxxMutation()`). 화면에서 axios·`fetch` 를 직접 부르지 않는다.
- **쿼리 키는 생성된 키 함수로** — 무효화·프리페치에 손으로 쓴 배열 키를 쓰지 않는다. 의존 조회는 `enabled` 로 막는다.
- **URL 상태는 공용 URL 훅으로만** — 화면에서 `useSearchParams` 의 setter 를 꺼내지 않는다(읽기는 허용).
- **화면(views)에서 `useMemo`·`useCallback`·`React.memo` 를 성능·포커스 안정화 기본 수단으로 넣지 않는다** — 컴포넌트 분리·로컬 state·key 안정화·데이터 흐름 단순화로 푼다.
- **훅 규칙을 지킨다** — 조건·반복 안에서 훅을 부르지 않는다. 파생값을 `useEffect` + state 로 동기화하지 않고 렌더 중에 계산한다. effect 는 외부 시스템 동기화에만.
- **리스트 key 는 안정된 데이터 ID** — 배열 index 금지(입력칸 포커스·상태가 다른 행으로 옮겨 간다).
- **공용 컴포넌트는 프로젝트 것을 쓴다** — 다이얼로그·드로어·표·알림 훅을 화면에서 새로 만들지 않는다. 정본(프로토타입)과 모양이 다르면 공용 컴포넌트를 정본 모양으로 감싸거나 넓힌다 (화면을 공용 컴포넌트 모양으로 바꾸지 않는다).
