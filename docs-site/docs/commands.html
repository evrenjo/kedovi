원본 commands.md

아래 명령은 모두 kedovi start 로 띄운 AI 채팅에서 말로도 된다 ("스프린트로 바꿔줘" · "FN-001 어디서 써?" · "리뷰는 GPT 로"). core 의 kedovi 스킬이 말을 명령으로 바꿔 실행하고, 팀 범위 설정은 실행 전에 무엇이 바뀌는지 보여 주고 확인받는다. 채팅 안에서 하지 않는 것은 kedovi start(에이전트 안에서 또 띄움) · kedovi init · kedovi remove(선택 화면 · 삭제) · kedovi notify setup(터미널 화면) 뿐이고, 그때는 AI 가 명령을 알려 준다.

kedovi --help 는 자주 쓰는 명령과 분류 8개(시작 · 설치 · AI · 모델 · 프로젝트 설정 · 팀 · 팀 규칙 점검 · 진행 · 기록 · 문서 · 알림 · 연동)만 보인다. 터미널에서는 분류를 골라 그 명령들을 보고, kedovi help <번호> 는 그 분류만, kedovi help --all 은 전체다. 명령마다 --help · -h 를 붙이면 그 명령의 사용법만 보이고 실행하지 않는다 (kedovi upgrade --help). upgrade · reset · install 은 모르는 옵션이 있으면 실행하지 않는다.

release 자세히#

단계하는 일멈출 조건
1. 배포 전 확인develop 머리와 같은 트리의 develop 파이프라인이 성공했는지, 그 파이프라인 뒤로 CI 설정(include 의 다른 프로젝트 파일 · ref)이 바뀌지 않았는지, repo 확인 명령(releaseCheck)이 통과하는지실패면 develop 파이프라인을 새로 돌리고 다시 판정. 그래도 실패면 멈춤
2. release MRdevelop → release MR. 열린 MR 은 다시 쓴다MR 을 만들 수 없음
3. MR 파이프라인끝까지 기다린다실패 · 취소 · 시간 초과
4. 머지충돌 · 승인 · 파이프라인을 확인하고 머지 (vars.gitlab.agentMerge)머지할 수 없음
5. release 파이프라인머지 커밋의 파이프라인을 끝까지실패 · 안 생김
6. 운영 배포 (--deploy)배포 수동 작업을 실행하고 끝까지작업 없음 · 배포 실패
  • 파이프라인은 하나씩: 같은 repo(repos[].gitlab.runnerGroup 이 같으면 그 repo 들까지)에 도는 파이프라인이 있으면 끝난 뒤 다음 단계로 간다.
  • 일시 오류: 실패한 작업 로그 끝부분이 레지스트리 · 네트워크 일시 오류 모양(i/o timeout · connection reset · TLS handshake timeout · proxyconnect · 레지스트리 502/503/504 · 러너 시스템 실패)이면 그 작업만 vars.gitlab.retryMax(기본 2)번까지 다시 실행한다. 모양은 vars.gitlab.retryPatterns 로 더한다. 그 밖의 실패는 바로 멈춘다. 운영 배포 작업은 일시 오류여도 다시 실행하지 않고 다시 실행 명령을 보이며 멈춘다 (반쯤 적용된 배포 보호, vars.gitlab.retryDeploy 를 켜면 다시 실행).
  • repo 설정(workspace.json 의 repos[].gitlab): deployJob(배포 작업 이름) · releaseCheck(확인 명령. 환경변수 KEDOVI_RELEASE_SHA · KEDOVI_RELEASE_TREE · KEDOVI_RELEASE_PIPELINE 을 받고 끝 코드 0 이면 통과) · runnerGroup.
  • 끝 코드: 0 끝 · 1 실패 · 3 승인 · 선택 필요 · 4 시간 초과 · 5 파이프라인이 안 생김. 쓰는 법은 운영 검증 의 「release 명령」.

  • add 는 설정(runner-watch.json) · macOS launchd plist(기본 600초) · Linux systemd service · timer 를 만들고 등록 명령을 보인다. 등록은 러너가 도는 머신에서 사람이 한다. 기본 폴더는 이 PC 의 ~/.config/kedovi/runner-watch/<프로젝트>/, --repo R 이면 repos/R/ops/runner-watch/ 에 스크립트까지 복사한다 (다른 머신으로 옮겨도 돈다).
  • check 는 새로 생기거나 풀린 경보만 알린다 (같은 경보는 notify.repeatMin 분마다). 알림 명령이 실패 코드를 내면 다음 주기에 다시 보낸다. --dry-run 은 알림 · 정리 없이 보이기만.
  • 캐시 상한: docker 빌드 캐시가 cache.docker.builderKeepGB 를 넘으면 그만큼만 남기고, 회수 가능한 이미지 중 imageUntilHours 지난 것을 지운다. 러너 캐시 폴더(cache.dirs)는 maxGB 를 넘으면 경보, cache.clean 을 켜면 오래된 것부터 지운다.
  • 토큰은 파일에 쓰지 않는다: 환경변수 → kedovi secret → git credential.

◇ 워크스페이스 repository 주소 → 지금 커밋·push 할까요?   (원격이 없으면 주소부터, 예를 누르면 push 까지)

Esc 는 이전 질문으로(첫 질문에서는 취소), Ctrl+C 는 전체 취소. 폴더는 마지막 "이대로 만들까요?" 에서 예를 누른 뒤에만 만든다. 프로젝트 폴더를 미리 만들 필요 없이 상위 폴더에서 kedovi init 한다 (그 이름의 빈 폴더 안에서 해도 겹쳐 만들지 않는다). 안에 파일이 있는 폴더·이미 워크스페이스인 곳은 막는다. 워크스페이스 안에서 실행하면 바로 멈추고 kedovi type 을 알린다 (분석·설계 → 구축처럼 유형이 바뀌어도 같은 워크스페이스에서 바꾼다). repo 이름은 주소 끝 폴더명에서 자동으로 정한다. 스택·역할·브랜치는 workspace.json 에서 고치고 kedovi sync. 스크립트로 만들 때는 node <킷>/bin/kit.js init <폴더> --type new|modernization --packs … --docs … --legacy ….
