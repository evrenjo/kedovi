5. AI 연결 방식과 모델 프로필

원본 workflow.md

연결 방식은 init(팀 리더)과 install·kedovi agent(팀원·개인)에서 묻고, 사람마다 다르므로(구독·게이트웨이) 이 PC 에만 저장한다. 직접 연결이면 고른 회사마다 요금제를 묻는다. 요금제는 여유도(빠듯 · 넉넉 · 종량)로 바뀌어 자동 팀 구성에서 리더가 회사별로 모델을 나누는 기준이 된다. 이 PC 로그인 정보(~/.claude.json · ~/.codex/auth.json)의 요금제를 미리 골라 두고, 나중에 로그인 값이 저장한 값과 달라지면 sync 가 알린다. 게이트웨이는 종량으로 본다. 화면 없이: kedovi ai plan claude|gpt <요금제> [--team]. 모델 프로필과 메인(리드) 모델은 init 에서만 묻는다(팀 기본값, 메인은 workspace.json agents.main). 프로필을 고른 뒤 메인만 따로 올릴 수 있다(예: 표준 + 메인 Opus). 팀원의 이 PC 프로필은 kedovi models profile <이름> 으로만 두고, 팀과 같거나 낮은 것만 적용된다.

구성역할 모델
두 회사 모델 섞기아래 표 그대로. 리뷰·테스트 등을 다른 회사 모델이 맡는다
한 회사 모델만다른 회사 칸은 같은 회사 대체 모델(fallback)로. 교차 검토는 쓰지 않는다
단일 모델모든 역할이 메인 모델. 역할 에이전트는 그대로 불러 대화 context 를 아낀다

구성은 "쓰는 AI" 에서 자동으로 정해진다 (두 회사 = 섞기, 한 회사 = 한 회사 모델만). 단일 모델은 kedovi ai compose single.

다른 회사 모델을 쓰는 방법은 연결 방식에 따라 다르다.

연결Claude Code 세션의 GPT 역할Codex 세션의 Claude 역할
AI 서비스 직접delegate.js 로 Codex 에 위임delegate.js 로 Claude Code 에 위임
AI 게이트웨이하위 에이전트로 바로 (역할 파일 모델 = 게이트웨이 모델 ID). GPT 를 메인으로도 쓸 수 있다위임 (Codex 안에서 Claude 모델은 도구 호출이 끊겨 쓰지 않는다)

Codex 는 역할 파일(.codex/agents)을 하위 에이전트에 적용하지 않아서(0.158 확인), 개인 지침의 「팀 구성」 표(자동이면 리더가 고른 모델)대로 리더가 spawn_agent 에 모델·추론 강도를 넣는다.

팀 구성 모드는 새 워크스페이스가 자동(리더가 작업마다 역할 · 등급 · 모델을 골라 구성표를 알리고 시작), agents.mode 가 없는 옛 워크스페이스가 고정(프로필대로)이다. kedovi team-mode 로 바꾼다.

진행 방식은 새 워크스페이스가 유형마다 정해진다 (신규 구축은 init 에서 MVP · 워터폴, 운영·고도화는 이슈형 · 스프린트 · 전체 중 고른다): 신규 · 운영·고도화 = MVP · 스프린트(기능 단위 스프린트. 끝까지 동작하는 최소 기능부터 만들고 나머지는 백로그, 스프린트마다 데모 · 회고하며 하나씩 붙임), 차세대 · 분석·설계 = 워터폴 · 전체(전체 범위를 설계한 뒤 구축). 신규 구축은 두 방식 모두 첫 단계가 「아이디어 · 전체 그림」(무엇을 왜 만드는지 대화 → 기능 지도 → MVP 범위, 건너뛸 수 있음)이다. project.approach 가 없는 옛 워크스페이스는 전체처럼 동작하고, kedovi upgrade 가 고르는 법을 알린다. kedovi approach 로 바꾼다. 이슈마다 운영에 반영하는 운영 · 유지보수는 이슈형(단계 대신 이슈 보드)이다. 프로필 선택 화면은 시작 도구와 연결 방식을 반영한 표를 보여 준다. 역할 에이전트 상한(한 요청에 동시 · 모두)은 프로필마다 정해져 있다 (절약 1·3, 표준 2·5, 최고 3·8). workspace.json·.agents/local.json 의 agents.limits 로 바꾼다. 이 PC 값은 팀 값보다 낮게만 적용된다.

괄호는 추론 강도(effort). 없으면 역할 정의(packs/core/agents/*.md)의 값. 메인의 추론 강도는 kedovi start 가 넘긴다 (Claude --effort, Codex -c model_reasoning_effort).

모델이 정해지는 순서: 프로필 → 팀이 역할별로 직접 고른 값 → 이 PC 에서 직접 고른 값. 이 PC 프로필은 팀과 같거나 낮은 것만 적용한다 (높은 것은 리더가 kedovi models allow-higher on 으로 허용). 상한은 팀 값 이내.

참고: 모델 목록 원본은 packs/core/models.json

팀과 다른 값이 적용 중이면 세션 시작 줄과 kedovi start 에 모델 프로필: 이 PC 절약 (팀 표준 대신) · 되돌리기 kedovi models profile team · 상한 동시 2 · 모두 5 (팀 4 · 10) 로 보인다.
