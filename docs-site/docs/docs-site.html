원본 docs-site.md

문서 사이트: kedovi docs build 가 기획 repo(kind: docs)의 모든 md 를 같은 경로 구조의 HTML 로 docs-site/ 에 만든다. README.md(없으면 INDEX.md)는 그 폴더의 목록 페이지이고, 0.59.0 전의 html/ 은 처음 build 때 옮긴다.

참고: 옮길 때 git mv · CI 의 cp · artifacts · 주석 경로도 고친다. 고친 줄 수를 알리고, 못 고친 줄은 「⚠ .gitlab-ci.yml N행에 html/ 경로가 남음」 으로 알린다.

  • 화면 틀은 이 가이드와 같다: 상단 바(로고 · 사이트 이름 · 검색 ⌘K: 제목 · 소제목 · 본문 · ID · 버전 · 펜 필기 · 인쇄 · 라이트/다크, 오른쪽 단추는 같은 크기의 선 아이콘) · 왼쪽 구분 메뉴(문서 # 제목) · 본문 머리(구분 · 상태 · 원본 버튼) · 오른쪽 「이 페이지」 목차 · 이전/다음. 스타일은 가이드와 한 파일(packs/core/assets/docs-site/site.css)이다.
  • 새로고침 없는 이동: 메뉴 · 이전/다음 · 본문 링크 · 검색 결과를 누르면 그 쪽 파일에서 본문만 읽어 바꾼다. 메뉴 접힘 · 필기 켜짐 · 검색창은 그대로이고, 뒤로 가기는 그 쪽의 읽던 자리로 돌아간다. 링크에 마우스를 올리면 미리 읽는다. 주소는 지금처럼 쪽마다 .html 이라 공유 링크 · 근거 색인 · 화면설계서와 ERD 의 근거 패널이 그대로 쓴다. file:// 로 열면 이동만 새로 연다.
  • 옛 주소 · 캐시: 문서를 다른 폴더로 옮기면 옛 주소에 「옮겨졌습니다」 쪽이 남아 새 주소로 바로 넘긴다 (파일 이름이 같은 새 쪽이 하나일 때. 짝은 assets/site.json 의 moved). 쪽이 부르는 assets/ 파일 주소에는 내용 해시(?v=)가 붙어, 다시 만든 뒤 브라우저가 옛 메뉴 파일을 쓰지 않는다.
  • 본문 검색: 검색은 정의 ID(앞부분) · 문서 제목 · 소제목에 더해 본문 글자도 찾는다. 낱말 앞부분이 맞으면 찾고(「설치」 로 「설치를」 도), 긴 영문 낱말은 오타 하나도 봐준다. 결과에 맞은 곳 앞뒤 글자를 보이고, 누르면 그 절로 간다. 본문 색인(assets/search-text.js, 절마다 앞 4,000자)은 처음 검색할 때만 읽는다.
  • 문서 목록 쪽(폴더 쪽 · README 쪽 아래)은 메뉴 묶음마다 제목 + 표로 나눈다.
  • 메뉴 묶음 기본값: 폴더마다 한 묶음, 루트는 「시작」(루트 README 는 ## 마다 한 쪽). 한 폴더에 파일 이름 앞 번호 띠(00 · 10 · 20 …)가 여럿이면 띠마다 나누고, 이름은 그 띠 문서 제목들의 공통 낱말이다.
  • 바꾸기: 기획 repo 의 docs-site.json. groups[].files 는 나열한 순서대로 메뉴에 나오고(glob 하나에 맞는 여러 문서는 파일 이름 순), 어느 묶음에도 안 맞는 문서는 「기타」 로 가며 build 가 ⚠ 로 알린다. split 은 true(그 묶음 전부) 또는 [glob](그 파일만)이면 ## 마다 한 쪽. labels({ "README.md": "소개" })는 메뉴에 보일 이름만 바꾼다. files 의 폴더/** 는 그 폴더 아래 전부다.
  • md 해석: GitLab · GitHub 화면과 같은 규칙(CommonMark + 표 · 취소선)으로 읽는다 (markdown-it). 한국어 조사가 바로 붙은 굵게(**확정(초안)**은)도 굵게로 보이고, 목록 항목 안의 코드 · 표, 백틱 여럿인 인라인 코드, 역슬래시 이스케이프(\|)도 된다. 맨 앞 YAML 머리(--- … ---)는 보이지 않는다. 긴 표 칸을 접을 때 굵게 · 코드 · 링크 중간에서는 끊지 않는다.
  • 보안: md 안의 HTML 은 글자로 보이고(표 칸의 <br> 만 줄바꿈), 줄 앞의 <!-- … --> 주석은 보이지 않는다 (GitHub 와 같게). 링크는 http(s) · mailto · 사이트 안 문서만 걸고(javascript: 등은 글자만), 파일 이름이 주소 체계처럼 보여도(javascript:x.md) 상대 주소로 건다. 「원본」 버튼은 source 가 http(s) 일 때만. 스크립트 · on… 속성 · javascript: · 끼워 넣은 문서(iframe 등)가 든 SVG 는 문자 참조로 감춰도 사이트에 넣지 않고 ⚠ 로 알린다. kedovi docs serve 는 이 PC 주소(127.0.0.1 · localhost)로 온 요청에만 답한다. 화면설계서 장 HTML 과 docs-site.extra.js 는 그대로 들어가므로 repo 에 쓸 수 있는 사람만 고치게 한다.
  • 메뉴 접기 · 폴더 트리: 모든 묶음은 제목을 눌러 접고 편다. 메뉴 맨 위 줄은 「🏠 홈」(첫 화면)과 오른쪽 토글 하나: 펼친 묶음이 있으면 모두 접기, 모두 접혀 있으면 모두 펴기 (아이콘 · 툴팁이 다음 동작). ERD 목록도 같은 줄을 쓴다. 묶음에 "collapsed": true 면 처음엔 접힌 채이고(없으면 처음엔 펼침), "tree": true 면 묶음 안 문서를 폴더대로 접히는 트리로 보인다 (history/2024/… → 2024 ▸ …). 지금 보는 문서가 든 묶음 · 폴더는 늘 펴지고, 바꾼 접힘 상태는 브라우저에 사이트별로 기억한다.
    { "group": "커밋 이력", "files": ["20-history/**"], "collapsed": true, "tree": true }
  • 인쇄: 상단 인쇄 단추 → 「이 문서 인쇄」(접힌 곳을 펴고 그림을 그린 뒤) · 「전체 문서 인쇄」(print-all.html 이 메뉴 순서대로 모든 문서 본문을 불러와 문서마다 새 쪽으로 이어 붙이고 인쇄 창을 연다. PDF 로 저장하면 문서 전체 한 파일. docs-site.json 에 "printAll": { "autoPrint": false } 면 인쇄 창을 열지 않고 다 불러왔다는 안내만). 넓은 표는 인쇄 때 쪽 너비에 맞추고 칸 안에서 줄을 바꾼다. 전체 인쇄는 웹 주소(Pages · kedovi docs serve)로 열었을 때만 되고, file:// 로 열면 안내만 보인다. 화면설계서 · ERD 처럼 따로 뜨는 쪽은 링크만 넣는다.
  • 펜 필기: 상단 펜 단추로 켜고 끈다 (켠 채 다른 쪽으로 옮겨도 켜져 있다). 본문 위에 펜 · 형광펜 · 지우개(획을 지우고 범위를 원으로 보인다)로 쓰고, 펜 선은 필압 · 속도에 따라 굵기가 바뀐다 (펜이 아니면 속도로 흉내 낸다), 도구마다 색 5가지 · 크기 4단계, 자(흔들려도 곧은 선, 가로 · 세로 · 45° 에 붙음. 마우스는 Shift 를 누른 동안도) · 되돌리기(⌘Z · Ctrl+Z) · 이 쪽 모두 지우기 · PNG 받기(필기만) · 끝내기(Esc). 필기는 이 기기 브라우저에 쪽마다 저장되고 인쇄에도 나온다. 끄려면 docs-site.json 에 "ink": false.
    필기를 켠 동안펜한 손가락두 손가락
    펜(Apple Pencil · S Pen)이 닿은 뒤필기화면 이동 (브라우저 기본 스크롤)쓰지 않음 (확대도 안 됨)
    펜이 없을 때없음필기화면 이동 (확대 안 됨)

    화면 이동(펜이 없을 때의 두 손가락 · 마우스 휠 · 트랙패드)은 손가락 · 포인터가 있는 자리의 요소로 간다. 넓은 표 · 코드 · 그림 위면 그 상자가 먼저 움직이고, 끝에 닿았거나 움직일 상자가 없으면 쪽 전체가 움직인다. 펜이 닿은 뒤의 손가락 스크롤은 쪽 전체가 움직인다 (넓은 표를 옆으로 밀려면 필기를 끈다).

    참고: 펜은 처음 닿을 때 알아채고 이 기기 브라우저에 기억한다. 펜이 닿아 있는 동안에는 손가락으로 화면이 움직이지 않는다. 손바닥은 OS 가 거른다. 필기를 켠 동안에는 확대가 되지 않는다 (확대하려면 필기를 끈다). 필기는 본문 위치에 붙는다. 창 너비가 바뀌면 같은 비율로 늘고 줄지만, 글 줄바꿈이 달라지면 조금 어긋날 수 있다. 다른 기기 · 다른 사람과는 나누지 않는다.

  • 로고: docs-site.json 의 logo 가 먼저다. 없으면 사이트 이름 첫 낱말이 2~3자 영문 약어일 때 그대로 대문자(「XD 분석」 → XD), 아니면 앞 두 낱말의 첫 글자.
  • 이 repo 만의 모양 · 동작: 기획 repo 맨 위(docs-site.json 옆)에 docs-site.extra.css · docs-site.extra.js 를 두면 build 가 assets/site.css · site.js 끝에 붙인다. check 와 pre-commit 도 붙인 결과로 비교하므로 되돌렸다 붙일 일이 없다. 쪽을 옮겨도 extra.js 는 처음 한 번만 돈다. 쪽마다 할 일은 DS.on("page", function (e) { … }) 로 건다 (e.el = 본문, e.meta = 쪽 정보).
  • 메뉴는 한 파일: 왼쪽 메뉴는 쪽마다 넣지 않고 assets/nav.js 하나에 두고 앱이 그린다 (검색 색인 search.js 와 같은 방식, file:// 에서도 열린다).

    근거: 문서 1,000개 견본에서 사이트가 87.5MB → 2.6MB, 쪽 평균 88KB → 2KB

  • 구성: 정적 파일만이라 서버 없이 Pages · 아무 웹 서버 · file:// 에서 열린다. 빌드 도구는 쓰지 않는다.

    assets/site.js앱: 머리 줄 · 메뉴 · 검색 · 목차 · 그림 · 인쇄 · 필기. Preact + htm 으로 그린다 (원본은 킷의 packs/core/assets/docs-site/src/)

  • 포함 범위: docs-site.json 의 include · exclude(glob, 폴더/** 는 그 폴더 전체). 워크스페이스 루트를 만들면(kedovi docs build .) repos/<이름>/ 을 repo 마다 copy(사본) · link(그 repo 로 가는 쪽 하나만) · off(뺌)로 넣는다. 기본은 종류별(legacy = off, 그 밖 = copy)이고 "repos": { "docs": "link", "<이름>": { "mode": "copy" } } 처럼 종류나 이름으로 바꾼다 (link 의 url 로 그 repo 의 Pages 주소).
  • 원본 버튼: 하위 repo 문서는 그 repo 의 원격(workspace.json 의 repos[].url, 없으면 그 repo 의 origin) + 기본 브랜치 + repo 안 경로로 간다. 원격이 없으면 버튼을 숨긴다.
  • 대소문자만 다른 경로: 출력 경로가 대소문자만 다르면(같은 폴더의 README.md 와 INDEX.md 등) macOS · Windows 에서 서로 덮어쓰므로 build 가 ✖ 로 두 원본을 알리고 쓰지 않는다.
  • 크기: build 가 「docs-site/ n개 · 크기: 묶음별 내역」 과 repo 마다 넣은 방식을 한 줄씩 보이고, 20MB 를 넘으면 ⚠. kedovi upgrade 는 아직 커밋한 적 없는 docs-site/ 를 git add 안내에서 빼고 따로 알린다 (Pages 로 올릴 때만 커밋).
  • 그림(mermaid): md 의 ```mermaid 블록(flowchart · sequenceDiagram · erDiagram 등)을 그림으로 그린다. 라이트/다크를 바꾸면 다시 그리고, 그림 위 「확대」(더하기 · 빼기 · 맞춤 · Esc) · 「새 창」으로 크게 본다. 문법이 틀리면 그 자리에 오류 문구와 원문이 보이고 페이지는 그대로다. mermaid 11.17.2(MIT)를 킷 assets 에 넣어 그림이 있는 사이트에만 docs-site/assets/mermaid/ 로 복사한다 (오프라인 · file:// 에서도 열린다). kedovi docs build · check 가 문법 오류를 ✖ 로 알리고, check 와 기획 repo pre-commit 은 실패로 끝난다. 상자 · 화살표 문자로 그린 ASCII 그림은 ⚠ 로 mermaid 로 바꾸라고 알린다. 폴더 나무 · 화면 모양처럼 그림이 아닌 것은 코드 블록에 언어를 달면(```tree · ```screen) 알리지 않는다.
  • 인용구(>): 부가 설명 · 근거 · 출처용. 흐린 회색 막대와 흐린 글씨로 본문보다 작게 보이고, 「출처:」 · 「근거:」 · 「참고:」 로 시작하는 줄은 더 작은 출처 줄이 된다.
  • 읽기: 표를 읽기 쉽게 바꿔 보인다 (원본 md 는 그대로).
    • 긴 표 칸(vars.docs.cellFold, 기본 200자 넘음): 첫 문장만 보이고 「더 보기」 로 펼친다. 날짜 항목이 쌓인 칸(머리말 「변경」 등)은 첫 항목 + 「나머지 n건 보기」.
    • 결정 기록 표(첫 칸이 결정 ID, 머리에 「결정」 과 대안 · 이유 · 영향 중 하나): 한 줄 목록(ID · 결정 · 상태)으로 보이고, 누르면 나머지 칸이 카드로 펼쳐진다. #ID 로 열면 펼친 채로 간다.
    • 넓고 칸이 긴 표(4칸 이상 · 칸 평균 40자 넘음): 좁은 화면에서 행마다 카드(칸 이름 + 값)로 바뀐다.
    • 정의 ID 링크는 밑줄 없는 작은 배지로 보인다.

  • Pages (선택): repo 마다 켜고 끈다. kedovi init 이 기획 repo 를 넣을 때 묻고, 나중에는 kedovi docs pages on | off [repo] (인자 없이 = 상태).

    • off: .gitignore 에 /docs-site/ 를 넣어 이 PC 에서만 본다 (kedovi docs serve 로 http://127.0.0.1:8000/ 에서 연다. file:// 로도 열리지만 쪽 이동이 새로고침이 되고 전체 인쇄가 안 된다). CI 파일은 docs-site/ 가 커밋돼야만 돌므로 두어도 된다.
    • kedovi docs build 가 끝날 때 그 repo 의 Pages 켜짐 여부와 바꾸는 명령을 한 줄로 알려 준다.
  • 다른 생성기가 만든 docs-site/ 가 있으면 덮지 않는다 (--out <폴더> 로 다른 곳에).

데이터 설계(datamodel 팩, 신규 · 차세대 유형은 기본으로 켜짐. 다른 유형은 kedovi upgrade --add datamodel):

  • 정본은 md 테이블 정의서: 스키마마다 <스키마>.md, 테이블마다 「### <스키마>.<테이블> <논리명>」 + 설명 줄(기능: FN-… · 결정: … · 파티션: … · 보존: … · 고정 스키마: <근거>) + 컬럼 표(컬럼 | 논리명 | 타입 | 널 | 키 | 참조 | 설명). DB 외래키 없이 앱이 지키는 참조는 키에 FK 없이 참조 칸에 논리: <스키마>.<테이블>[.<컬럼>](논리 참조). 견본은 packs/datamodel/assets/erd/template.md, 기획 repo 에는 40-data/_template.md (옛 뼈대는 06-data/). 폴더 README.md 에 엔티티 목록 · 컨벤션 표.
  • ERD 뷰어: kedovi docs build 가 정의서가 든 폴더마다 <폴더>/erd.html 을 만든다 (손으로 고치지 않는다). 배치는 elkjs(EPL-2.0, 킷 assets 에 넣어 오프라인에서도 열린다).
    • 배치 3가지: 영역(설명 줄 「영역: …」 이 있으면 기본. 스키마 상자 안에 영역 덩어리를 화면 비율에 맞춰 바둑판으로 놓고, 덩어리 안은 부모 → 자식 위에서 아래로. 덩어리 사이 선은 숨긴다) · 스키마(스키마마다 상자, 스키마 사이 관계선은 옅게) · 관계(묶지 않고 관계있는 테이블끼리 가깝게, 영역이 없으면 기본).
    • 영역 개요: 영역이 있으면 처음에 영역마다 카드 하나(영역 이름 · 테이블 수 · FK · 논리 참조 수 · 대표 테이블)로 연다. 카드를 누르면 그 덩어리로 확대하고, 목록에서 표를 고르면 그 표로 간다. 「맞춤」 으로 전체를 맞췄을 때 영역 이름을 읽을 수 없을 만큼 작아지면 개요로 보인다. 「영역 사이 선」 을 켜면 덩어리 사이 FK 를 덩어리 → 덩어리 요약선 하나에 개수로 보인다.
    • 논리 참조(기본 꺼짐): 켜면 촘촘한 점선으로 그린다. 영역 배치에서 덩어리 사이 논리 참조는 요약선 하나에 개수(「논리 n」). 상세 드로어에 논리 참조 · 받음 목록, Export DDL 은 끝에 주석으로. 많이 참조되는 테이블(종목 · 사용자 · 코드)이 있어도 세로로 길어지지 않게 층마다 테이블 수에 상한을 둬 가로로 넓게 편다. 스키마 드롭다운(찾기 · 전체 선택/해제)으로 보일 스키마를 고른다.
    • 이름 보기 3가지(논·물리명 · 논리명 · 물리명, 브라우저에 기억) · 표시 수준(Display Level: 테이블 · 키 · 컬럼, 「자동」 이면 확대 비율로 바뀌는 시맨틱 줌). [테이블] 수준은 테이블이 많아 줄여 볼 때도 글자가 화면에서 같은 크기로 보인다.
    • 돋보기(줄여 볼 때 카드에 마우스를 올리면 전체 컬럼) · 테이블을 누르면 연결만 강조 + 상세 드로어(컬럼 · 참조함 · 참조받음 · 기능 ID · 파티션 · 보존, Esc · × · 빈 곳 클릭으로 닫힘). 기능 · 결정 ID 와 「정의서」 를 누르면 오른쪽 근거 패널에 그 문서가 열린다.
    • 미니맵(오른쪽 아래): 전체 배치를 스키마 색으로 줄여 보이고 지금 보이는 영역을 사각형으로 표시한다. 누르거나 끌면 그 자리로 간다. 접고 펴기는 브라우저에 기억, 인쇄 · SVG 에는 넣지 않는다.
    • 참조 많은 표 선 숨김(기본 꺼짐, 브라우저에 기억): 들어오는 관계가 10개 이상인 테이블(vars.datamodel.erdHubMin) · 코드 테이블(설명 줄 「분류: 코드」) · 「ERD: 선 숨김」 · vars.datamodel.erdHideEdgesTo 로 가는 선을 숨기고 그 선 없이 배치한다. FK 꼬리표는 그대로, 그 테이블을 고르면 숨긴 선도 보인다.
    • 주제 영역: 설명 줄에 「영역: 주문」 처럼 달면 상단에 「영역」 선택이 생겨 고른 영역만 그린다. 영역 밖 테이블과의 관계는 상자 아래 「→ 영역 밖: …」 한 줄로. 사이드바는 스키마 → 영역 → 테이블로 접는다. 영역이 일부 테이블에만 있으면 kedovi datamodel check 가 ⚠.
    • 사이드바 스키마 접기: 스키마 제목 줄(화살표)을 누르면 표 목록을 접고 편다. 목록 맨 위 줄 「테이블 n」 오른쪽 토글이 모두 접기 ↔ 모두 펴기 (문서 메뉴와 같은 부품). 검색에 맞는 표가 있는 스키마는 저절로 펼친다. 접힘은 브라우저에 기억. 제목 줄의 ⌖ 는 그 스키마 상자에, 영역 줄의 ⌖ 는 그 영역 덩어리에 맞춘다.
    • 관계선은 1:N(참조 받는 쪽 ┼ · 참조하는 쪽 ⋔), 널 허용 FK 는 점선. 단축키 / 0 + − F Esc, #스키마.테이블 주소, 다크 모드.
    • 손 조작 · 좁은 화면: 한 손가락(마우스) 끌기 = 이동(표 · 카드 위에서 시작해도), 두 손가락 = 확대 · 축소, 휠 · 트랙패드 = 확대 · 축소. 캔버스에서는 브라우저의 화면 확대 대신 그림이 커진다 (iPad 포함). 캔버스가 좁으면(세로 iPad 등) 배치 · 선 · 이름 · 표시 수준은 「보기 ▾」 한 메뉴로 접고 확대 단추만 한 줄에 두며, 머리 줄은 왼쪽(← 문서 · 제목) · 오른쪽(스키마 · 영역 · Export) 양끝에 검색은 아래 줄 전체 폭.
    • Export: SQL DDL(전체 스키마 · 보이는 스키마만, vars.datamodel.dialect 문법. 범위 밖 FK 는 주석) · SVG · A4 가로 PDF(지금 보이는 그대로: 숨긴 선 · 고른 영역) · 영역마다 한 쪽 PDF. DDL 은 검토용이다 (실제 변경은 마이그레이션 도구로).
  • 사이트: 데이터 설계 묶음의 첫 항목(폴더 README 쪽)이 개요가 되어 맨 위에 스키마 · 테이블 · 관계 수와 「▶ ERD 보기」 를 보인다. 묶음 제목 옆 ▶ 도 ERD 로 간다. 뷰어의 「← 문서」 는 그 개요로 돌아간다.
  • DB 컨벤션은 프로젝트가 정한다: datamodel 스킬이 이름 규칙 · 기본키 타입 · 공통 컬럼 · 삭제 방식 · 시점 · 금액 타입 · 코드값 방식 · 외래키를 DB 에 걸지 · DB 종류를 하나씩 묻고(권장안은 packs/db/rules/60-data-modeling.md 기본값), 답을 workspace.json 의 vars.datamodel 에 둔다. 검사기와 Export 가 읽는다. 비운 값은 검사하지 않는다.
  • 절차: datamodel 스킬 (진행 방식 합의 → DB 컨벤션 → 엔티티 목록(기능 ID 대조) → 스키마별 정의서 → ERD · 검사 → 사이트 반영). 검사는 kedovi datamodel check. 「기능: 없음」 · 「공통 컬럼: 없음」 · 엔티티 목록의 「없음」 줄은 세지 않는다. 「고정 스키마: <근거>」 테이블(프레임워크가 만드는 테이블, 예: Spring Batch 메타 테이블)은 기본키 없음을 ⚠ 로 낮추고 이름 · 공통 컬럼 · 타입 규칙은 보지 않는다. vars.datamodel.jsonReason 을 Y 로 두면 JSON 컬럼 설명에 「JSON 허용: <사유>」 가 없을 때 ⚠.
