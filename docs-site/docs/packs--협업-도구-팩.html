<details> <summary><b>github</b> · GitHub 팀 워크플로: 브랜치 전략 · PR 생성 · 이슈 등록 · 커밋 규칙</summary>

GitHub 협업: 브랜치 전략(작업 브랜치 → PR, 머지는 사람만), 커밋 메시지, 이슈·PR 어조, gh CLI 로 PR 을 만드는 스킬, 이슈 찾기 · 읽기 · 등록 · 조치 보고 댓글 스킬

항목내용
붙는 조건repo 주소가 GitHub 인 repo 에
함께 붙는 팩core

규칙

ID제목읽는 때
github--10-branch-and-merge브랜치·PR·머지 원칙상시
github--20-commit-message커밋 메시지상시
github--30-issue-pr-tone이슈·PR 본문 어조와 확인 항목 양식필요할 때: 이슈 문서·GitHub 이슈·PR 본문·리뷰 코멘트·코드 담당자에게 보내는 확인 요청을 쓸 때
github--40-branch-detail브랜치 전략 상세필요할 때: 브랜치를 새로 따거나, PR 방향(head→base)·hotfix·브랜치 이름을 정할 때

스킬

이름설명
github-issueGitHub 이슈를 찾고 · 읽고 · 등록하고 · 조치 보고를 댓글로 단다. 초안 → 비슷한 이슈 · 민감정보 검사 → 사용자 OK → gh issue create / comment. 닫기 · 라벨 · 담당자는 하지 않는다. "이슈 등록해줘", "#12 이슈 봐줘", "조치 내용 이슈에 남겨줘" 요청에 쓴다.
pr지정한 head→base 로 GitHub 풀리퀘스트를 만든다 (base 생략 시 통합 브랜치). 미리보기 → 사용자 OK → gh pr create → 팀 배포 안내까지. 머지는 하지 않는다. "PR 만들어줘", "QA PR" 요청에 쓴다.

<details> <summary><b>gitlab</b> · GitLab 팀 워크플로: 브랜치 전략 · MR 생성 · 이슈 등록 · 파이프라인 조회 · 배포 연쇄(대기 · 머지 · 수동 작업) · 커밋 규칙</summary>

GitLab 협업: 브랜치 전략(작업 브랜치 → MR, 머지는 사람만. vars.gitlab.agentMerge 를 켜면 지시받은 MR 만 에이전트가), 커밋 메시지, 이슈·MR 어조, MR 생성 스킬, 이슈 찾기 · 읽기 · 등록 · 조치 보고 댓글 스킬, 파이프라인 조회(kedovi gitlab pipeline) · 수동 작업 실행 · 다시 실행(--play · --retry: manual 이 될 때까지 기다린 뒤 실행하고 끝날 때까지 상태, --yes 없이는 확인 문구만), 배포 연쇄 명령(kedovi gitlab wait · merge · play · retry · cancel, create 는 열린 MR 을 다시 씀)

항목내용
붙는 조건repo 주소가 GitLab 인 repo 에
함께 붙는 팩core
비밀값GITLAB_TOKEN (프로젝트): MR 생성 · 이슈 등록 · 파이프라인 조회 · 권한 api

규칙

ID제목읽는 때
gitlab--10-branch-and-merge브랜치·MR·머지 원칙상시
gitlab--20-commit-message커밋 메시지상시
gitlab--30-issue-mr-tone이슈·MR 본문 어조와 확인 항목 양식필요할 때: 이슈 문서·GitLab 이슈·MR 본문·코드 담당자에게 보내는 확인 요청을 쓸 때
gitlab--40-branch-detail브랜치 전략 상세필요할 때: 브랜치를 새로 따거나, MR 방향(source→target)·hotfix·브랜치 이름을 정할 때

스킬

이름설명
gitlab-issueGitLab 이슈를 찾고 · 읽고 · 등록하고 · 조치 보고를 댓글로 단다. 초안 → 비슷한 이슈 · 민감정보 검사 → 사용자 OK → 등록 · 댓글. 닫기 · 라벨 · 담당자는 하지 않는다. "이슈 등록해줘", "#12 이슈 봐줘", "조치 내용 이슈에 남겨줘" 요청에 쓴다.
mr지정한 source→target 으로 GitLab 머지리퀘스트를 만든다 (target 생략 시 통합 브랜치). 미리보기 → 사용자 OK → 생성 → 팀 배포 안내까지. 머지는 사람이 한다 (agentMerge 를 켠 워크스페이스는 지시받은 MR 만 배포 연쇄로). "MR 만들어줘", "QA MR", "배포해줘" 요청에 쓴다.

도구: bin/gitlab-issue.js · bin/gitlab-mr.js
